# 3. デザインの軸と情報設計

最新の表示・操作仕様は[HTMLモック](../mock/README.md)を正とする。この資料は、モックの外観だけでは伝わらない目的と判断理由を記録する。寸法・色値・配置・操作の詳細はモックを参照し、Hugoテーマへの実装方法は実装フェーズで検討する。

実装中はモックを凍結し、資料4の合意と、その後に承認した変更を併せて比較基準にする。変更の記録・本資料への反映・再検証は[実装規律](05-theme-implementation-discipline.md)に従う。

## コンセプト

「控えめな装飾で本文へ集中できる、日本語の技術文書のためのテーマ」を目指す。ミニマルかつタイポグラフィを強調したデザイン体系で技術記事の長文・コード・図表を読みやすくし、日記や写真も同じ体系で受け止める。

ライトモード・ダークモードに両対応し、シンタックスハイライトに用いる[Catppuccin Latte/Mochaのカラーパレット](https://catppuccin.com/palette/)をサイト全体に適用することで、コードブロックが文書の一部として自然に溶け込む構成を目指す。

PaperModのミニマルさを出発点に、和欧文の混植、見出しの強弱、余白の関係を日本語の読書に合わせる。統一感は文字・余白・階調の関係からつくる。[riq0h](https://riq0h.jp/2026/07/21/194535/)はサイト名の存在感と控えめな記事タイトルのバランス、[Zenn](https://zenn.dev/zenn/articles/markdown-guide)・[Qiita](https://qiita.com/Qiita/items/c686397e4a0f4f11683d)は技術文書の読みやすさの参考とする。

デザインの基準は記事本文。共通ヘッダーや読後の操作も、本文を読む流れの中で存在感を決める。実記事の内容・長さ・画像の有無が異なっても、同じサイトとして落ち着いて読めることを重視する。

## 情報設計

### 読者の目的による役割分担

| 場所 | 役割と判断理由 |
| --- | --- |
| ホーム | ブログの入口として、短い紹介から新着記事へつなぐ。著者個人の紹介より、サイトと記事を主役にする |
| About | 著者を詳しく知るための公開文書。継続的に更新・共有される内容として、鮮度や反応を記事と共通の考え方で扱う |
| 記事一覧・個別タグ／カテゴリ | タイトルに要約やカバーを添え、関心に合う記事を選ぶ材料を提供する。分類は話題から記事へ入る入口とする |
| Archives | 時期やタイトルの記憶から過去の記事を探す。記事を選ぶための一覧とは情報の密度を分ける |
| 記事詳細 | 一つの内容を読み進める場。読み終えたところから分類・共有・前後の記事へつなぐ |
| フッター | 著者の活動や継続的な購読につなぐ。個々の記事を共有する操作とは目的を分ける |

記事探索のナビゲーションと配色設定は役割を分ける。サイト名と記事を探す導線が中心軸をつくり、配色は読者が読書環境を調整するための操作として扱う。

一覧も記事間移動も、新着から過去へ読み進める流れを共通にする。左のPrevは新しい記事、右のNextは古い記事とし、画面を移っても方向の意味を保つ。

日付は内容の鮮度を判断する手がかりとする。更新日は公開日との日付の違いを伝える情報として扱い、同じ年月日の時刻差は区別しない。

### コンテンツと補助UIの言語

読者向けの固定UIは短い英語で揃え、操作・状態を簡潔に伝える。記事本文・タイトル・分類名などは書き手の言語を保つ。補助UIの一貫性と、日本語の文章を自然に読むことを両立する。

## 書体と組版の考え方

### 環境に合った書体と和欧文の調和

書体選定では、各環境での読みやすさと、和欧文それぞれのウェイトによる階層を優先する。端末間の字形の違いは許容し、端末に備わる書体を基本に、最終的な代替は読者のブラウザ設定へ委ねる。

- Apple環境ではSan Franciscoとヒラギノ、WindowsではSegoe UIとNoto Sans JPの調和を重視する。Apple標準の指定だけでは和文がヒラギノになるとは限らないため、和文フォントも明示的に指定する。Windowsでは游ゴシックによる和文のかすれを避けるため、`system-ui`でのシステムUI書体への一括委任は採用しない。
- 見出しは本文より一段強いウェイトとサイズ・余白で階層を示し、文中の強調ははっきりとした太さで区別する。サイト名は本文と書体を共有し、軽いウェイトでリズムをつくる。
- Windows 11のFirefoxでは、見出しの500指定がSegoe UI Semiboldではなく通常書体になるとの実機報告がある。Chrome/EdgeではSemibold、サイト名300は3ブラウザともLight。見出しはサイズでも識別できるため、この書体選択の差異を許容し、今回の移行では修正を見送る（F022、2026-09-18）。
- 本文の字間は、日本語フォントが持つプロポーショナルメトリクスを生かし、括弧や句読点を含む混植の自然さを重視する。
- コードでは欧文の等幅性を優先し、和文はコードとしての字幅と読みやすさで評価する。本文用の和文候補を共有すると、欧文用のコード書体がない環境でプロポーショナルな欧文が選ばれるため、本文とは候補を分ける。

本文サイズは、Safariの和文が小さめに見えるという実機確認も踏まえ、モバイルでも読みやすさを確保する判断としている。

### 本文のリズムとUIの寸法を分ける

見出し・補助文字・大きな区切りには、本文を起点とするモジュラースケールを用いる。リスト内部の間隔や字下げは、文章に近い小さな関係として本文基準の分数で整理する。本文の大きさを変えても、階層とまとまりが一緒に保たれることを狙う。

操作部品の寸法や内部余白は共通の刻みで揃える。本文のリズムと操作のしやすさを別々に調整できるよう、組版とUIは独立した尺度を持つ。両者とも読者の文字サイズ設定に応じて拡大できることを重視する。

行高は、文章を読む・見出しを捉える・ラベルを識別する・表を比較する・コードを追うという役割で分ける。同じ値になっていても役割の区別を保ち、数値の一致だけを理由にまとめない。

余白は情報の関係を表す。見出しと続く本文、親見出しと子見出し、画像と説明など、関連する情報を近づけ、独立するまとまりを離す。整列は文字や図柄の見える位置を重視しつつ、操作領域が画面内に収まることを優先する。

## 配色と本文部品

ライト・ダークを同等の読書環境として設計する。[Catppuccin](https://catppuccin.com/palette/)のLatte／Mochaを基調とし、文章とコードが一体に見える配色を目指す。公式のシンタックスハイライトとコード背景を維持し、ページ側の配色に調整の余地を持たせることで、統一感と領域の識別を両立する。

公式配色の維持は、すべてのコード文字色のコントラスト確保に優先する判断である。一部の色にはコントラスト上の制約があり、サイト全体のアクセシビリティ適合を保証するものではない。

意味の識別に必要な強さと、装飾の強さを分ける。引用の境界は引用であることを伝えるため、一般の区切り線より識別しやすくする。リンクは文章の色を保ちながら下線で見つけやすくし、操作時には下線を強めて反応を伝える。

画像は技術的な情報を持つ場合があるため、元の内容と縦横比を尊重する。画像同士の見かけの高さより、スクリーンショットや図の情報が読めることを優先する。

コードは文章を補う内容として扱う。短いコードでも補助操作が主役にならないよう、コピーの操作領域と見た目の存在感を分ける。言語やファイル名は、そのコードに属する情報としてまとめる。

コードブロックの行高は1.4とする。Windows実機で行間が詰まって見えるとの報告を受け、全環境で読みやすさを改善するため、凍結モックの1.3から変更する。インラインコードは周囲の行高を引き継ぐ（F023、2026-09-18ユーザー承認）。

Aboutの業務経験表は「業務経験／技術／経験年数」の列見出しを使う。空の見出しを解消し、画面表示と読み上げの双方で列の意味を伝える。経歴・技術・年数は維持する（F014、2026-09-18ユーザー承認）。

## 控えめな装飾と操作性

自作アイコンは、サービスの識別性を保ちつつ共通の線画に揃え、サービスごとの視覚的な強さよりサイト全体の静けさを優先する。図柄の大きさと操作領域を分け、小さく見える操作にも押しやすさを確保する。

連続するテキストリンクでは、文字間隔の自然さと操作領域を両立する。独立したボタンの寸法をそのまま当てはめるより、文章に近い並びとして評価する。キーボードのフォーカスは、控えめな装飾とは別に、操作位置を明確にする役割を持つ。

見出しリンクは特定の節を共有するための補助とし、読書中の存在感を抑える。タッチ主体の環境では、常設の記号より本文の静けさを優先する。コードコピーは内容を利用するための操作として、タッチ・キーボードからも使えるようにする。

## 共有・反応・購読の役割

共有は記事を外へ届ける操作、はてなスターは記事に付く反応として区別する。共有側の外観はサイトに揃え、スターは反応を表示する公式ウィジェットの性質を尊重する。共有と反応は記事・Aboutの公開URLに結び付け、同じ内容への参照を保つ。

RSSは著者のプロフィールを見るリンクとは異なり、継続して読むための入口とする。既存の購読先や記事への参照を引き継ぎ、テーマの変更を読者の継続利用につなげる。移行元の調査は[資料2](02-papermod-analysis.md)を参照する。
