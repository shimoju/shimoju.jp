# 4. 自作テーマの視覚要件

合意した要件と最新モックの仕様。詳しい実装理由は[資料5](05-theme-implementation.md)、確認手順は[資料6](06-theme-validation.md)、閲覧方法は[モックREADME](../mock/README.md)を参照。

## 位置付けとデザインの軸

日本語の技術文書を読みやすくし、技術記事以外の日記・写真にも適用できる自作テーマを目指す。PaperModからは一列構成、控えめな装飾、本文への集中を引き継ぐ。カード枠・影・面分けは引き継がない。

- 本文は日本語ゴシック体。Webフォント・明朝体は採用しない。
- 文字・余白・階調を揃える。通常の見出しに下線・背景色・色付きの縦線を付けない。
- ライト／ダークを同等に設計する。コードブロックはCatppuccin Latte／Mochaの公式配色を維持する。
- サイドバー、固定ヘッダー、固定目次、トップに戻るボタン、装飾的なアニメーションは設けない。
- ここに記載したルールを実装の基準にする。寸法の微調整は実記事の可読性と階層を保った範囲で行う。

今回の成果物は静的HTMLモックと視覚要件。Hugoテーマの完成実装、SEO・性能、全記事移行、公開・外部サービス接続は別工程。資料1〜3は調査資料であり、採否については本資料を優先する。

## 対象画面・状態・幅

| 対象 | 内容 |
| --- | --- |
| 記事詳細 | デザインの基準。長文・短文、長いタイトル、カバーあり／なし、更新あり／なし、タグなし |
| ホーム | サイトタイトル、短い紹介、新着順の記事、ページ送り。Aboutは共通ヘッダーのみとし、紹介文下には重複表示しない。X・GitHubは共通フッターへ移動 |
| About | 詳しいプロフィールと全リンク。記事の日付・タグ・シェア・スター・前後記事は表示しない |
| 記事一覧 | 見出し、必要なら説明、共通の一覧、ページ送り |
| タグ／カテゴリ一覧 | 分類名と件数。塗りつぶしたチップではなく文字を中心に折り返す |
| 個別タグ／カテゴリ | 分類の見出し、必要なら説明、共通の一覧 |
| Archives | 年→月→タイトルと日付。要約・カバーなし |
| 404 | 控えめな見出しと説明、Home・Archivesへの復帰導線。巨大な404を主役にしない |

検索・Profileモードは実装しない。目次も実装しない。

一覧は初・途中・最終ページ、0件・1件・多数、画像・要約の有無を確認する。紹介文はホーム初ページのみ。ページ送りは存在する移動先だけを表示し、初ページのPreviousと最終ページのNextはラベルごと省く。1ページしかない場合はページ送り自体を省く。静的HTMLでもこの表示を実現する。

全画面を400px／1280px・両配色で確認し、320px・360px・768pxで収まりを追加確認する。400pxは代表幅であり最低幅やブレークポイントではない。実装上の切り替え幅は640pxを初期値とする。狭い幅や拡大相当の幅では本文を折り返し、コード・表だけを局所的に横スクロールさせる。

## 情報設計と共通UI

- 中央のサイトタイトルを主役にし、その下にAbout／Archives／Categories／Tagsと配色切り替えを置く。
- サイトタイトルのサイズとヘッダー上余白は全ページで共通にする。サイズ1.931rem、上余白4.096rem／2.560remとする（デスクトップ／モバイル）。ブラウザの既定文字サイズ16pxではサイズ約32.83px、上余白約69.63px／43.52pxに相当する。見出しと同じスケールの7段目を使い、ページ間の位置変化を抑える。
- 記事タイトル・本文は左揃え。ホームに独立した著者名の見出しは置かない。
- 文脈から明らかな「新着記事」「公開」「シェア」の可視ラベルを省く。ホームのH1はサイトタイトルとする。
- 更新日には公開日との区別に必要なラベルを残す。
- フッターは中央揃えの2段。1段目にX・GitHub・RSS、2段目に© 2026 Hiroshi Shimojuを置く。「RSSを購読」とは表記しない。RSSの自動検出も維持する。
- ナビはモバイルでも隠さず折り返す。配色ボタンだけにホバー背景を付けることはしない。
- 読者向け操作語を統一する。モックの表記はPrevious / Next / Copy / Copied / Updated / RSS。記事本文とレビュー説明は日本語。実装時にUI文言を確定する。
- OS設定を初期値とし、手動選択後はライト／ダークの選択を保持する。二状態ボタンとし、システム設定に戻すUIは作らない。次の切り替え先がアイコン・読み上げラベルで分かるようにする。

## タイポグラフィ

### 採用確定

| 項目 | 採用値 |
| --- | --- |
| ルートサイズ | 全画面幅で106.25%。pxで固定しない |
| 本文サイズ | 1rem（ブラウザの既定文字サイズ16pxでは17px） |
| 記事タイトル | 1.6rem（既定文字サイズ16pxでは27.2px） |
| サイトタイトル | 1.931rem。見出しと同じスケールでH1の2段上 |
| コードサイズ | calc(14 / 17 * 1rem)（既定文字サイズ16pxでは全画面幅で14px） |
| コード行高 | 1.3 |
| 本文リンク | 本文色＋下線。text-underline-offsetは0.26em。ホバーでBlueへ変更しない |
| 本文・記事見出しの書体 | Apple標準＋Segoe UI、和文はHiragino Sans／Noto |
| サイト名の書体 | 本文・記事見出しと共通 |

本文の左揃え、自然な和欧文混在、一行を長くしすぎないことを必須にする。本文・見出しは`font-feature-settings: "palt";`を適用し、フォントが持つプロポーショナルメトリクスを使う。一律の負のletter-spacingによる追加の字詰めはしない（欧文サイト名の既存値−0.025emは維持）。本文は最大720px、左右ガター24px／20px（デスクトップ／モバイル）・行高1.9・太さ400・段落間隔1emを初期値として維持する。

見出しの前を広く、後を狭くし、続く本文とまとめる。下位見出しを本文より小さくしない。

見出しサイズは`1rem × 1.6^(n / 5)`を小数第3位に丸めた値とする。本文・H6を0段、H5〜H1を1〜5段、サイトタイトルを7段に置く。CSSには計算済みの定数を記載する。行高は維持し、見出しのem指定の余白は文字サイズに追従する。

補助文字は同じスケールの−1／−2／−3段を用い、0.910／0.829／0.754remに揃える。一覧タイトルは＋2段の1.207rem。要約・ナビ・ページ送り・脚注・表・Archivesの月は0.910rem、日付・タグ・キャプションは0.829rem、小さなラベル・著作権表示は0.754rem。要約とナビの文字サイズはモバイルでも共通とする。

大きな余白は役割別トークンにする。本文画像・表・コードの前後は1.931em、カバーの上は1.931rem。記事一覧の区切り・ページ見出しの下は2.560rem、年別アーカイブ・脚注の上は3.089rem、記事末尾・デスクトップヘッダーの下は3.394rem、デスクトップヘッダーの上・ページ送りの上は4.096rem。モバイルヘッダーは上下2.560rem。記事一覧は罫線の前後にgapとpaddingの両方があるため、合計の間隔で評価する。段落1em・引用1.6em、コード内部・インラインコードの余白、操作対象の最小寸法は維持する。

本文内のH2〜H6の余白は前2.121em・後0.687emに統一する。見出し自身の文字サイズに対する割合であり、本文先頭の要素は上余白0とする。記事タイトルの余白はこの共通指定に含めない。

| 要素 | 採用値（rem）。本文に対する比率と共通 |
| --- | ---: |
| H2 | 1.456 |
| H3 | 1.326 |
| H4 | 1.207 |
| H5 | 1.099 |
| H6 | 1 |

文字と操作部品のサイズ・余白は原則rem、周囲の文字に追従するインラインコード・段落・リストの余白などはem、行高は単位なしとする。本文の最大幅720px、左右ガター、ブレークポイント、細い罫線・角丸などはpxを維持する。文字を含む部品は固定高さで切らず、min-heightと折り返しを使う。

記事タイトル・本文見出し・一覧タイトルは太さ500・行高1.5を基本とする（一覧タイトルの行高はモックの1.6を維持）。フォント候補は本文と共通にし、ローカルフェイスの別名定義は使わない。H5／H6の差は小さいため、長い見出しや前後の文章を含めて確認し続ける。サイト名も見出しの一種として500に揃え、Archivesの月は補助情報として400を維持する。

本文は400、見出しは500、強調のstrong／bと表のthは700とする。strongとbは意味の違いを保ちつつ外観を揃え、入れ子でも700を維持する。シンタックスハイライトが指定するbold（700）は変更しない。見出しはサイズ・余白でも階層を示し、本文の強調は文字の太さで通常の文章と明確に区別する。

### システムフォント

環境間で字形を統一せず、各環境に適した欧文と和文でウェイト500の階層が読み取れることを重視する。本文・記事見出し・サイト名は共通の候補順とし、Apple標準のSan Francisco、WindowsのSegoe UIを優先する。Macの和文をNotoより先に補完するためHiragino Sansを明示し、Windowsの欧文をヒラギノにしないためSegoe UIの後ろに置く。Noto候補もなければsans-serifへ委ねる。Webフォント・ローカル別名定義・system-uiは使わない。詳細は[実装上の判断理由](05-theme-implementation.md)を参照。

```css
--font-body: -apple-system, BlinkMacSystemFont, "Segoe UI", "Hiragino Sans", "Noto Sans JP", "Noto Sans CJK JP", sans-serif;
--font-code: Menlo, Consolas, monospace;
--font-site: var(--font-body);
```

コード・インラインコードはMenlo, Consolas, monospaceを採用確定とする。MacではMenlo、WindowsではConsolasを優先し、いずれもない環境と和文はブラウザのmonospace・不足文字のフォールバックに委ねる。Linux／Android等で欧文がプロポーショナル書体へ落ちるのを避けるため、和文フォントは明示指定しない。和文は等幅で読みやすいことを確認し、本文との書体の統一は要求しない。ui-monospaceは採用せず、SF Monoの名前指定もしない。palt・合字・自動カーニングは無効のまま。ブラウザが最終的に選ぶ書体や和欧文の厳密な2:1の幅比は保証しない。根拠は[実装上の判断理由](05-theme-implementation.md)を参照。

モックのレビュー画面に現在のfont-familyを表示する。CSS変数から取得し、候補順の説明と和欧文サンプルを添える。これは文字ごとに実際に使われたフォントの特定ではない。

CSSのフォント選択は半角／全角分類ではなく文字の収録状況に基づく。コードの日本語1文字が必ず欧文2文字分になるとは仮定しない。[CSS Fonts](https://www.w3.org/TR/css-fonts-4/#font-family-prop)

`palt`は括弧・句読点だけに限定されず、フォントによって仮名などの字幅も変える。字形の置き換えではなくGPOSによる幅・位置の調整であり、フォント側の対応が必要。コードブロック・インラインコードでは`font-feature-settings: normal`に戻し、字幅を保つ。[OpenType palt](https://learn.microsoft.com/en-us/typography/opentype/spec/features_pt#tag-palt)

確認したヒラギノ、公開版Noto Sans JP／Noto Sans CJK JPにはpaltがある。欧文候補自体にpaltがなくても、後続の日本語フォントへの適用は可能。確認した版と範囲は[実装上の判断理由](05-theme-implementation.md)を参照。本文の明示候補にBIZと游ゴシックは加えず、Notoの後はsans-serifに委ねる。コードには和文候補を追加せずmonospaceに委ねる。Windows同梱版や端末ごとのフォールバックでpaltの効果を一律に保証しない。

### コードブロック

- calc(14 / 17 * 1rem)・行高1.3、細い境界、小さな角丸、十分な内側余白を基本にする。
- 長い行は折り返さず、コード内で横スクロールする。コピーは常時表示する。
- 言語指定がある場合のみ言語を表示する。ファイル名は指定がある場合のみ表示し、本文から推測しない。
- Hugoのコードブロックレンダーフックで、言語は `.Type`、ファイル名は `.Attributes.filename` を取得する。フェンスの `filename="config.toml"` はHugoの属性記法を利用したカスタム表示であり、標準Markdownに自動表示機能があるという意味ではない。
- 言語もファイル名もない場合はラベル文字を出さず、コピーを右に置く。言語あり／なしでツールバーとコピーのpadding・高さ、本文上余白を統一する。ラベルのない箇所に余白が生じてもよい。初期値はツールバー上下0.25rem・左右1.125rem／0.625rem、コピー最小高さ2.25rem・padding 0.375rem 0.5rem、コード本文上0.75rem。ラベルとボタンは必要なら折り返し、高さが伸びる。
- 行番号は通常表示せず、指定時のみ対応する。言語なし、未対応言語、行番号、強調行も確認する。
- コピー成功時はボタンの表示だけを変更し、3秒後に元へ戻す。ブロック下部の可視メッセージは出さない。読み上げ用通知は視覚レイアウトを変えずに提供する。
- 失敗時は成功表示にせず、ボタンで失敗と再試行が分かるようにする。
- インラインコードは同じ等幅フォントを使い、本文の行高を押し広げない。文字サイズは周囲の文字の0.85倍（0.85em。既定文字サイズ16pxの本文中では14.45px）、paddingは上下0.25em・左右0.35em。背景を行高いっぱいに厳密固定せず、隣接行の背景が接触しない隙間を残す。部品ページでpaddingなしの同一文と行送りを照合する。コードブロックはcalc(14 / 17 * 1rem)で別管理する。

## 記事詳細

記事タイトル → 日付（必要なら更新日）→ 任意のカバー → 本文 → タグ → シェア・はてなスター → 前後記事の順。

著者名の毎記事での反復、読了時間、文字数、パンくず、編集リンク、トップに戻るボタンは表示しない。Aboutには記事用の周辺情報を付けない。

シェア先はX・Facebook・はてなブックマーク。はてなスターはシェアと別の操作として区別する。Xのシェアにタグ由来のハッシュタグは付けない。モックでは送信しないローカルな状態表示とし、本実装でサービスへ接続する。

## 記事一覧・カバー・クリック範囲

一覧カバーはデスクトップでも本文幅いっぱいを採用する。基準のカバー画像は1200×630とし、720px幅なら高さ378px。高さを360pxなどに制限して幅まで縮める処理をしない。ほかの比率の画像も切り抜かない。

一記事につき任意のカバー → タイトル・日付・要約（まず3行）の順にまとめる。カバーはタイトルの上に固定し、DOM順も表示順と揃える。記事詳細のタイトル → 日付 → カバーの順序は変更しない。画像がどの記事に属するか分かるように、内側の間隔を小さく、記事間を広くする。記事間の細い区切り線も維持する。囲みカードや塗りつぶし背景は作らない。

- ホームを含む共通一覧では、タイトル・日付・要約・画像を一つのリンクにする。
- Archivesではタイトルと日付を同じリンクに含める。
- タグ・カテゴリの分類名と件数も、余白込みで押せる範囲を確保する。
- 記事全体をクリック可能にした場合、タイトルのホバー下線は付けない。
- ネイティブのリンクを使い、新しいタブで開く操作、キーボード移動、フォーカスの識別を維持する。リンクの入れ子や、同じ記事への重複した停止位置を避ける。
- 押せる範囲を広げることだけで、アクセシビリティ全般への適合を保証しない。

## 検証と成果物

基本画面の両配色・基準幅、追加幅、通常／ホバー／キーボードフォーカス、コピー成功／復帰／失敗、配色切り替え、拡大相当のリフローを確認する。ホバーだけで存在が分かる操作にはしない。フォーカス輪郭は残す。

実記事を優先し、不足するH2〜H6、引用、長い表、脚注、和欧文混在、言語なし・日本語コメント付きコード、画像とキャプションは部品ページで補う。

成果物には全対象画面、実際のデザイントークン、実装に必要な理由と検証手順を含める。別OS・別ブラウザやWCAGへの適合を、単一環境のモック検証だけで保証しない。
