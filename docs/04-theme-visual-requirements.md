# 4. 自作テーマの視覚要件

合意した要件と最新モックの仕様。詳しい実装理由は[資料5](05-theme-implementation.md)、確認手順は[資料6](06-theme-validation.md)、閲覧方法は[モックREADME](../mock/README.md)を参照。

## 位置付けとデザインの軸

日本語の技術文書を読みやすくし、技術記事以外の日記・写真にも適用できる自作テーマを目指す。PaperModからは一列構成、控えめな装飾、本文への集中を引き継ぐ。カード枠・影・面分けは引き継がない。

- 本文は日本語ゴシック体。Webフォント・明朝体は採用しない。
- 文字・余白・階調を揃える。通常の見出しに下線・背景色・色付きの縦線を付けない。
- ライト／ダークを同等に設計する。コードブロックはCatppuccin Latte／Mochaの公式配色を維持する。
- サイドバー、固定ヘッダー、固定目次、トップに戻るボタン、装飾的なアニメーションは設けない。
- ここに記載したルールを実装の基準にする。寸法の微調整は実記事の可読性と階層を保った範囲で行う。

今回の成果物は静的HTMLモックと視覚要件。Hugoテーマの完成実装、SEO・性能、全記事移行、本番公開は別工程。シェア・はてなスターはモックでも実サービスへ接続する。資料1〜3は調査資料であり、採否については本資料を優先する。

## 対象画面・状態・幅

| 対象 | 内容 |
| --- | --- |
| 記事詳細 | デザインの基準。長文・短文、長いタイトル、カバーあり／なし、更新あり／なし、タグなし |
| ホーム | サイトタイトル、現行のホーム紹介文、新着順の記事、ページ送り。Aboutへのリンクは共通ヘッダーに置く。X・Bluesky・GitHubは共通フッターに置く |
| About | 現行About本文を維持する。日付・シェア・はてなスターを表示し、タグ・前後記事は表示しない |
| 記事一覧 | 見出し、必要なら説明、共通の一覧、ページ送り |
| タグ／カテゴリ一覧 | 分類名と件数。塗りつぶしたチップではなく文字を中心に折り返す |
| 個別タグ／カテゴリ | 分類の見出し、必要なら説明、共通の一覧 |
| Archives | 年→月→タイトルと日付。要約・カバーなし |
| 404 | 控えめな見出しと説明、Home・Archivesへの復帰導線。巨大な404を主役にしない |

検索・Profileモードは実装しない。目次も実装しない。

ページ送りは左に`« Prev`・中央にページ番号・右に`Next »`を1行で配置する。短いラベルで必要幅を抑え、番号の別行化や縦配置は行わない。

本実装の一覧は現行どおり1ページ10件。モックはページ送り検証用の2件×3ページを維持する。

タグ・カテゴリ一覧はHugo標準の名称順（`Alphabetical`）に従い、独自の五十音・読み仮名ソートは実装しない。

一覧は初・途中・最終ページ、0件・1件・多数、画像・要約の有無を確認する。紹介文はホーム初ページのみ。本文はHugo設定の`params.homeInfoParams.content`から取得し、名前の独立見出しは追加しない。AboutはHugoのページ本文から描画し、文章をテンプレートへ固定しない。ページ送りは存在する移動先だけを表示し、初ページのPrevと最終ページのNextはラベルごと省く。1ページしかない場合はページ送り自体を省く。静的HTMLでもこの表示を実現する。

全画面を400px／1280px・両配色で確認し、320px・360px・768pxで収まりを追加確認する。400pxは代表幅であり最低幅やブレークポイントではない。実装上の切り替え幅は640pxを初期値とする。狭い幅や拡大相当の幅では本文を折り返し、コード・表だけを局所的に横スクロールさせる。

## 情報設計と共通UI

- 中央のサイトタイトルを主役にし、その下にAbout／Archives／Categories／Tagsを中央揃えで置く。配色切り替えはナビから独立させ、ヘッダー右上の余白に配置する。操作領域の右端を本文コンテナの右端に揃え、SVGの光学的な右補正は行わない。操作領域48px相当と上下8px相当の余裕を確保し、狭い幅・文字拡大時もサイト名と重ならないようにする。
- サイトタイトルのサイズとヘッダー上余白は全ページで共通にする。サイズは本文の1.931倍。上余白は本文サイズの4.096倍／2.560倍を基準とし（デスクトップ／モバイル）、配色切り替えの操作領域と上下の余裕を合わせた64px相当を下限とする。ブラウザの既定文字サイズ16pxではサイズ約32.83px、上余白約69.63px／64pxに相当する。見出しと同じスケールの7段目を使い、ページ間の位置変化を抑える。
- 記事タイトル・本文は左揃え。ホームに独立した著者名の見出しは置かない。
- 文脈から明らかな「新着記事」「公開」「シェア」の可視ラベルを省く。ホームのH1はサイトタイトルとする。
- 更新日には公開日との区別に必要なラベルを残す。
- フッターのアイコンは共有アイコンとサイズ・本文色を共用し、下線は付けない。サービス名のアクセシブルなラベルを持つ。
- フッターは中央揃えの2段。1段目にX・Bluesky・GitHub・RSSのSVGアイコン、2段目に© 2026 Hiroshi Shimojuを置く。RSSの自動検出も維持する。
- ヘッダーナビ・一覧のページ送り・記事下部のタグと前後記事・Tags／Categoriesの分類リンク・Archivesの記事リンクは、通常時に下線を付けず、ホバー・キーボードフォーカス時に下線を表示する。ヘッダーの現在地リンクは常時下線を維持する。
- 常時下線は`--muted`（ライト#5c5f77／ダーク#bac2de）、ホバー・キーボードフォーカス時の下線は`--text`（ライト#4c4f69／ダーク#cdd6f4）とする。本文・引用・キャプション・脚注のリンクとヘッダーの現在地表示に共通適用し、操作時だけ現れる下線も`--text`とする。文字色は変えず、訪問済みリンクも同じ扱いとする。フォーカス輪郭は維持し、サイト名・見出しリンク・アイコンには下線を追加しない。
- Tags／Categoriesの分類リンクは、分類名だけにホバー下線を付け、件数には付けない。一覧の記事全体リンク・Archives・前後記事リンクは、ホバー時に記事タイトルだけへ下線を付ける。一覧の要約・日付、前後記事のPrev／Nextと記号には付けない。リンク全体のクリック範囲は維持する。サイトタイトルは常に下線なしとする。下線は太さ1px・オフセット0.26emとし、キーボードのフォーカス輪郭、本文中のリンクと脚注の常時下線を維持する。
- ナビはモバイルでも隠さず折り返す。シェア・プロフィール・配色・コピーのアイコン自体には、ホバーによる背景・枠線・色・サイズの変化を付けない。フォーカス輪郭・ポインターカーソル・操作結果の表示は維持する。コピーの背景と内枠は背後のコードから分離するため、表示中は常に付ける。
- ホバー時も文字・アイコンの前景色は通常時のままとする。見出しリンクはmuted、共有・プロフィールアイコンは本文色を維持し、見出しリンクの記号サイズは`--text-label`（本文の0.754倍）とする。テキストナビの下線、コピー・見出しリンクの表示切り替えで操作状態を示す。
- 記事末尾タグとTags／Categories一覧は文字の配置開始位置、シェア列は24px相当のSVG表示領域の左端を本文に揃える。列全体をタグ・分類は4px相当、シェアは12px相当左へ補正し、折り返した行にも適用する。サービスごとの図柄補正はしない。補正量は共通ガターを上限にし、文字拡大時などに足りなければ左揃えより操作領域の画面内への収まりを優先する。クリック領域・列内gapは維持し、対象リンクのフォーカス輪郭は内側に描く。中央揃えのフッターは補正しない。
- 読者向け操作語を統一する。操作ラベルはPrev / Next / Copy / Copied / Updated / RSS、Archivesの月名は英語とする。見出しリンクのtitleとaria-labelはLink to this section、langはenとする。記事本文、空状態・エラー説明、レビュー説明は日本語とする。
- 記事間移動と一覧のページ送りは、前方向に`«`、次方向に`»`を使う。ラベルは共通のPrev／Nextとし、postは付けない。記号と文字の間には半角スペースを置き、ラベル全体を一つのインライン整形コンテキストに収めてflex項目間で空白が消えないようにする。記号だけを`aria-hidden="true"`で読み上げ対象から外す。脚注の戻り記号は`↩︎`とする。
- OS設定を初期値とし、手動選択後はライト／ダークの選択を保持する。二状態ボタンとし、システム設定に戻すUIは作らない。次の切り替え先がアイコン・読み上げラベルで分かるようにする。
- 配色切り替えの月・太陽は、線幅を含む図柄の外周までviewBoxの内部余白を詰める。縦横比を保って16×16px相当の表示領域へ最大化し、線の欠けを防ぐ。操作領域は48×48px相当を維持する。

### システムフォント

環境間で字形を統一せず、各環境に適した欧文と和文でウェイト500の階層が読み取れることを重視する。本文・記事見出し・サイト名は共通の候補順とし、Apple標準のSan Francisco、WindowsのSegoe UIを優先する。Macの和文をNotoより先に補完するためHiragino Sansを明示し、Windowsの欧文をヒラギノにしないためSegoe UIの後ろに置く。Noto候補もなければsans-serifへ委ねる。Webフォント・ローカル別名定義・system-uiは使わない。詳細は[実装上の判断理由](05-theme-implementation.md)を参照。

```css
--font-body: -apple-system, BlinkMacSystemFont, "Segoe UI", "Hiragino Sans", "Noto Sans JP", "Noto Sans CJK JP", sans-serif;
--font-code: Menlo, Consolas, monospace;
--font-site: var(--font-body);
```

コード・インラインコードはMenlo, Consolas, monospaceを使う。MacではMenlo、WindowsではConsolasを優先し、いずれもない環境と和文はブラウザのmonospace・不足文字のフォールバックに委ねる。Linux／Android等で欧文がプロポーショナル書体へ落ちるのを避けるため、和文フォントは明示指定しない。和文は等幅で読みやすいことを確認し、本文との書体の統一は要求しない。ui-monospaceは採用せず、SF Monoの名前指定もしない。palt・合字・自動カーニングは無効にする。ブラウザが最終的に選ぶ書体や和欧文の厳密な2:1の幅比は保証しない。根拠は[実装上の判断理由](05-theme-implementation.md)を参照。

モックのレビュー画面に現在のfont-familyを表示する。CSS変数から取得し、候補順の説明と和欧文サンプルを添える。これは文字ごとに実際に使われたフォントの特定ではない。

CSSのフォント選択は半角／全角分類ではなく文字の収録状況に基づく。コードの日本語1文字が必ず欧文2文字分になるとは仮定しない。[CSS Fonts](https://www.w3.org/TR/css-fonts-4/#font-family-prop)

`palt`は括弧・句読点だけに限定されず、フォントによって仮名などの字幅も変える。字形の置き換えではなくGPOSによる幅・位置の調整であり、フォント側の対応が必要。コードブロック・インラインコードでは`font-feature-settings: normal`に戻し、字幅を保つ。[OpenType palt](https://learn.microsoft.com/en-us/typography/opentype/spec/features_pt#tag-palt)

確認したヒラギノ、公開版Noto Sans JP／Noto Sans CJK JPにはpaltがある。欧文候補自体にpaltがなくても、後続の日本語フォントへの適用は可能。確認した版と範囲は[実装上の判断理由](05-theme-implementation.md)を参照。本文の明示候補にBIZと游ゴシックは加えず、Notoの後はsans-serifに委ねる。コードには和文候補を追加せずmonospaceに委ねる。Windows同梱版や端末ごとのフォールバックでpaltの効果を一律に保証しない。

### コードブロック

- 1.4rem・行高1.3、細い境界、小さな角丸、十分な内側余白を基本にする。
- 長い行は折り返さず、コード内で横スクロールする。コピーは右上のSVGアイコンとし、コードのホバー・キーボードフォーカス・タップで表示する。非表示中はポインター操作を受けず、タップだけではコピーしない。
- 言語指定がある場合のみ言語を表示する。ファイル名は指定がある場合のみ表示し、本文から推測しない。
- Hugoのコードブロックレンダーフックで、言語は `.Type`、ファイル名は `.Attributes.filename` を取得する。フェンスの `filename="config.toml"` はHugoの属性記法を利用したカスタム表示であり、標準Markdownに自動表示機能があるという意味ではない。
- 常設ツールバーは設けない。言語・ファイル名がある場合だけ小さなラベルを上に置き、ない場合はコードから始める。外周の余白は上下左右とも`--code-inset`（1.6rem）、関連するラベルとコードの間はその半分の`--ui-space-2`（0.8rem）にする。ラベルは`--text-label`・行高1.5、右はコピー操作領域と余白の合計4.8remを確保し、長い名前は折り返す。コピーは右上から0.4rem内側、絵柄1.6rem・見える背景面2.4rem・実際の操作領域4remの正方形とする。操作領域を外にはみ出させず、ブロックの高さはコード・ラベル・余白で決め、最小高さは指定しない。表示前後でコードの幅・高さ・位置を変えない。
- 行番号は通常表示せず、指定時のみ対応する。言語なし、未対応言語、行番号、強調行も確認する。
- コピー成功時はチェック、失敗時は×のSVGに切り替え、英語のアクセシブルな名前・title・読み上げ通知でも結果を伝える。成功は3秒後に通常のコピーアイコンへ戻り、失敗は再試行できる。ブロック下部の可視メッセージは出さない。右上のコードにアイコンが重なる場合は、Escape・ブロック外のタップ・コードの横スクロールで隠せる。マウスが離れ、ブロック内にフォーカスもない場合は非表示にする。タップで表示した場合は明示的な操作まで保持する。文字選択やスクロールの標準操作は妨げない。JS無効時はコピーアイコンを出さず、コードの手動選択を利用できるようにする。
- 失敗時は成功表示にせず、ボタンで失敗と再試行が分かるようにする。
- インラインコードは同じ等幅フォントを使い、本文の行高を押し広げない。文字サイズは周囲の文字の0.85倍（0.85em。既定文字サイズ16pxの本文中では14.45px）、paddingは上下0.25em・左右0.35em。背景を行高いっぱいに厳密固定せず、隣接行の背景が接触しない隙間を残す。部品ページでpaddingなしの同一文と行送りを照合する。コードブロックは1.4remで別管理する。

## 記事詳細

更新日はHugoの`.Date`と`.Lastmod`の表示上の年月日が異なる場合だけ表示する。同日の時刻差だけでは表示しない。Hugo標準の日付補完を使用する。公開日・更新日の横gapは1.6rem、記事末尾のタグとTags／Categoriesの分類一覧は横gapを`--term-gap`（0.8rem）、リンクの左右paddingを`--term-inset`（0.4rem）で共通化する。分類名と件数の内部gapは0.4remとし、項目間より狭くする。縦gapは日付0.4rem・タグ0.8remとする。

記事詳細・About・記事一覧・Archivesのタイトルと日付の間隔は、共通トークン`--title-meta-gap`（0.8rem）で揃える。日付のない画面のH1はこの調整に含めない。

記事タイトル → 日付（必要なら更新日）→ 任意のカバー → 本文 → タグ → シェア・はてなスター → 前後記事の順。前後記事は全画面幅で新しい記事へのPrevを左列、古い記事へのNextを右列に置き、片方がなくても位置を維持する。左右同幅とし、列間はデスクトップ24px・モバイル16px。タイトルは省略せず折り返す。

著者名の毎記事での反復、読了時間、文字数、パンくず、編集リンク、トップに戻るボタンは表示しない。Aboutはタイトル → 日付 → 本文 → シェア・はてなスターの順とし、日付の表示・更新日判定は記事と共通にする。タグ・前後記事は付けない。

シェア先はX・Facebook・Bluesky・はてなブックマーク。はてなスターはシェアと別の操作として区別する。Xのシェアにタグ由来のハッシュタグは付けない。モックでも実サービスへ接続し、自作SVG＋通常リンクを採用する。はてなスターのみ公式ウィジェットを使い、背景の囲みは付けない。はてなブックマークは記事のブックマークページへ直接リンクする。記事・Aboutの公開URLを共有対象にする。[設定・確認範囲](07-theme-sharing.md)

## 記事一覧・カバー・クリック範囲

一覧カバーはデスクトップでも本文幅いっぱいを採用する。基準のカバー画像は1200×630とし、720px幅なら高さ378px。高さ上限は設けない。ほかの比率の画像も切り抜かない。

一記事につき任意のカバー → タイトル・日付・要約（3行を初期値とする）の順にまとめる。カバーはタイトルの上に固定し、DOM順も表示順と揃える。記事詳細ではタイトル → 日付 → カバーの順に置く。画像がどの記事に属するか分かるように、内側の間隔を小さく、記事間を広くする。記事間の細い区切り線も維持する。囲みカードや塗りつぶし背景は作らない。

- ホームを含む共通一覧では、タイトル・日付・要約・画像を一つのリンクにする。
- Archivesではタイトルと日付を同じリンクに含め、行高1.5の縦並びとする。行ボックス間のgapは`--title-meta-gap`（8px相当）。月名とその月の最初の記事は先頭行のベースラインを揃える。記事リンク間は24px、月のグループ間は32px、年のグループ間は本文基準の`--space-group`とする。末尾の記事・月には区切り用の余白を重ねない。
- タグ・カテゴリの分類名と件数も、余白込みで押せる範囲を確保する。
- 記事全体をクリック可能にし、ホバー時はタイトルだけに下線を付ける。要約・日付には付けない。
- ネイティブのリンクを使い、新しいタブで開く操作、キーボード移動、フォーカスの識別を維持する。リンクの入れ子や、同じ記事への重複した停止位置を避ける。
- 押せる範囲を広げることだけで、アクセシビリティ全般への適合を保証しない。

## RSS・OGP・埋め込み

RSSはPaperModの現行テンプレートの対象範囲・除外条件を踏襲する。home・section・taxonomy・termのフィード、要約形式・件数制限なし、既存URLとページごとのlink rel=alternateを維持する。詳細は[資料5](05-theme-implementation.md#rssとogpの互換性)を参照する。

OGP画像はカバーのある記事だけに指定する。カバーなし記事への共通画像・自動生成画像は初期実装に含めない。既存の外部埋め込みは本実装時に検証し、モックのX投稿リンク置換は維持する。

## 検証と成果物

UIの余白・寸法は4px相当を単位とし、8px刻みを中心にする。`--ui-space-N`は既定文字サイズ16pxで4×N px相当のrem値とする。コード本文の左右と言語ラベルの左余白は`--code-inset`（1.6rem）、シェア・プロフィールのgapは`--icon-gap`（1.2rem）を共用する。操作領域は`--control-size`（4.8rem）、コピー操作領域は専用の--copy-control-size（4rem）、コピー・配色SVGは共通の--icon-size-small（1.6rem）、共有・プロフィールSVGは--icon-size（2.4rem）とする。角丸は大8px（コード・画像・動画）、小4px（アイコン・ボタン・インラインコード等）に分け、配色切り替えの円形は別扱いにする。ページ左右ガターは基本24px、639px以下かつホバー不可の場合のみ16pxとし、見出しリンクを表示できる環境ではリンク操作幅2.4rem以上を確保する。本文基準のスケール・em指定・インラインコードの文字サイズとpaddingは変更しない。

独立した操作部品の最小高さは`--control-size`（4.8rem）（既定文字サイズ16pxで48px相当）に揃える。ヘッダーナビ・記事末尾のタグ・タグ／カテゴリ一覧は最小幅を指定せず、内容幅と横gapで文字間隔を整える。ページ送り・配色・シェア・プロフィールは最小幅も4.8remとし、アイコン操作領域は正方形にする。コピーは例外として縦横4remの操作領域と2.4remの背景面をコード右上に重ね、常設ツールバーは設けない。サイト名は最小幅・高さ4.8rem、記事一覧・前後記事・Archivesは最小高さ4.8remを確保し、幅と高さは内容に応じて伸ばす。文字を含むリンク・ボタンに固定高さを設定しない。本文内リンク・脚注は組版を維持し、はてなスターは公式ウィジェットとして別途確認する。

基本画面の両配色・基準幅、追加幅、通常／ホバー／キーボードフォーカス、コピー成功／復帰／失敗、配色切り替え、拡大相当のリフローを確認する。ホバーだけで存在が分かる操作にはしない。フォーカス輪郭は残す。

実記事を優先し、不足するH2〜H6、引用、長い表、脚注、和欧文混在、言語なし・日本語コメント付きコード、画像とキャプションは部品ページで補う。

成果物には全対象画面、実際のデザイントークン、実装に必要な理由と検証手順を含める。別OS・別ブラウザやWCAGへの適合を、単一環境のモック検証だけで保証しない。
