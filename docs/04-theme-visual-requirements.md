# 4. 自作テーマの視覚要件

合意日: 2026-09-06。grillingによるQ1〜Q36の議論と最終確認を反映した、モック作成のための要件。

## この資料の使い方

日本語の技術記事を読みやすくするため、PaperModのミニマルさを引き継ぎ、タイポグラフィ・余白・配色を一貫した体系として設計する。技術記事以外の日記や写真を含む既存コンテンツにも適用する。

| 区分 | 意味 | モックでの扱い |
| --- | --- | --- |
| 必須ルール | ユーザーと合意した方向性・表示内容・制約 | 各案で維持する |
| 初期値 | 最初に試す寸法・比率・色・配置の具体案 | 実記事を入れ、調整してよい |
| 比較項目 | 複数案を見て決める部分 | 指定した代表画面で比較し、結果を記録する |

数値を変える場合も、関連する部品を一緒に確認し、画面ごとに場当たり的な補正を増やさない。未確定の初期値はモック作成時の調整余地であり、全項目を文書段階で固定する必要はない。

今回の成果物は視覚要件の文書。モックそのものの制作、Hugoテーマの実装、SEO・配信・性能の詳細設計は別工程とする。[資料1](01-hugo-theme-structure.md)は画面とテンプレートの調査、[資料2](02-hugo-core-vs-theme.md)は責務の整理、[資料3](03-papermod-analysis.md)はPaperModの分析であり、今回の採否・見た目については本資料の合意を優先する。

## デザインの軸

- ページ全体を一列構成とし、本文に集中できることを重視する。一覧の各項目内ではテキストと小さな画像の横並びを許容する。
- 文字と余白を主役にする。PaperModのカード枠・角丸・面分けをそのまま引き継ぐ必要はない。
- 本文は日本語ゴシック体。明朝体は採用しない。
- 日本語と欧文の文字サイズ・行高・太さ・階層を整え、本文とコードが同じページの一部として調和するようにする。
- light/darkの両方を同等に設計する。コードはCatppuccin Latte/Mochaを厳密に維持し、サイト側は公式色を基本に、必要な範囲で派生色を許容する。
- 装飾的な動きは最小限にする。サイドバー、固定ヘッダー、固定目次、トップに戻るボタンは設けない。

## 対象画面と状態

すべての対象画面に、基本案のモバイル・デスクトップ、ライト・ダークの組み合わせを用意する。共通部品を使う画面でも、タイトルやデータの違いによる収まりを確認する。

| 画面 | 内容と役割 |
| --- | --- |
| 記事詳細 | デザインの基準。タイトル、日付、任意のカバー、本文、タグ、シェア・はてなスター、前後記事 |
| ホーム | サイトタイトル、短い紹介、GitHub・X、詳しい紹介へのAbout導線、新着記事、ページ送り |
| About | 詳しいプロフィールと全リンク。記事用の日付・タグ・シェア・スター・前後記事は出さない |
| 記事一覧 | 見出し、必要なら説明文、共通の記事一覧部品、ページ送り |
| タグ一覧・カテゴリ一覧 | 分類名と件数を並べ、横幅に応じて折り返す |
| 個別タグ・個別カテゴリ | 分類の見出し、必要なら説明文、共通の記事一覧部品、ページ送り |
| Archives | 年→月→記事タイトルと日付。要約とカバーは出さない |
| 404 | 「ページが見つかりません」という見出し、短い説明、ホームとArchivesへのリンク |

検索とProfileモードは実装対象外。目次は基本案に含めず、比較版のみで扱う。

一覧は初ページ・途中・最終ページ、0件・1件・多数、カバーあり・なし、要約なし、長いタイトルの状態を確認する。ホームの紹介は初ページに置く構成を基本案とする。

### 画面幅

| 用途 | CSS pxでの幅 |
| --- | --- |
| 基本モック | モバイル400px、デスクトップ1280px |
| 追加の収まり確認 | 320px、360px、768px |

400pxは比較・合意するための代表幅であり、最低対応幅やCSSのブレークポイントではない。レイアウトや文字サイズの切り替え位置は、内容が収まる幅から決める。狭い幅でも本文を固定幅のまま縮小せず、その幅に合わせて折り返す。

追加幅では、ナビゲーション、長いタイトル、本文、画像、表、コードと操作ボタンの収まりを確認する。追加幅用の独立した完成モックを全画面分増やす必要はない。320px相当の確認には、拡大時のリフローも考慮する。[W3C Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)

## 共通レイアウトとナビゲーション

### ヘッダー

- `shimoju.diary`を中央に置き、その下にAbout／Archives／Categories／Tagsと配色切り替えを配置する。
- ホームではサイトタイトルを大きく、その他のページでは控えめにする。記事タイトルと本文は左揃え。
- ヘッダーは固定しない。モバイルのナビゲーションは折り返して表示し、リンクを隠すメニューは基本案に設けない。
- 配色ボタンはナビゲーションの末尾に置く。現在地やフォーカスを識別できるようにする。

### ホームとフッター

ホームの紹介に「Hiroshi Shimoju」という独立した名前の見出しは置かない。短い紹介文と主要リンクを置き、新着記事へ続ける。紹介文は仮文でモックを始めてよい。

主要リンクの初期候補はGitHub・X。詳しいプロフィールと全リンクはAboutに集約する。RSSはSNSプロフィールとは役割が異なるため、フッターに独立した購読リンクとして置く。フッターは著作権表示とRSSなどの少数の要素に絞る。

RSSの自動検出用`link rel="alternate"`は実装時の事項であり、モックでは画面上の購読導線を扱う。

## タイポグラフィ

### 必須ルール

- Webフォントを使わず、ローカルで利用できるシステムフォントを使う。
- 欧文の候補を先に、和文の候補を後に指定するパターンを考慮する。端末間で字形が異なっても、読みやすさと階層を揃える。
- 本文は左揃え。過度な字詰めをせず、和欧文が自然に混在し、一行が長くなりすぎないようにする。
- 見出しはサイズ・太さ・前後の余白で区別し、通常の見出しに下線・背景色・色付き縦線を付けない。
- 見出し階層の強さを逆転させず、下位見出しも本文より小さくしない。記事タイトルが本文を圧倒しないようにする。
- 見出しの前を広く、後を狭くし、続く本文とのまとまりを作る。

CSSの`font-family`は半角・全角という分類で切り替える指定ではなく、対象文字を表示できるフォントを候補順に選ぶ。そのため、和欧文の字面・太さ・ベースラインは代表的な閲覧環境で確認する。[CSS Fontsのfont-family](https://www.w3.org/TR/css-fonts-4/#font-family-prop)

### フォント候補の初期案

具体的なファミリー順は調整可能。以下はWebフォントを取得せず、利用可能なローカル書体を順に試す候補であり、各端末に存在することを保証するリストではない。

```css
--font-body:
  "Helvetica Neue", "Segoe UI", Roboto, Arial,
  "Hiragino Sans", "Hiragino Kaku Gothic ProN",
  "Yu Gothic", Meiryo,
  "Noto Sans CJK JP", "Noto Sans JP",
  sans-serif;

--font-code:
  "SFMono-Regular", Menlo, Consolas, "Liberation Mono",
  "BIZ UDGothic", "MS Gothic",
  monospace;
```

`system-ui`を先頭にすると日本語まで解決され、後続の和文候補が使われない場合もある。OS任せの指定と、欧文・和文の候補を明示する指定の違いを考慮する。コードでは欧文の等幅と日本語コメントの判読性を確認し、異なる書体間で日本語1文字が欧文2文字分になることを前提にしない。[CSS Fontsの汎用フォント](https://www.w3.org/TR/css-fonts-4/#generic-font-families)

### 本文と見出しの初期値

| 項目 | 基本案 |
| --- | --- |
| 本文サイズ | デスクトップ17px、モバイル16px |
| 本文の最大幅 | 720px |
| 本文の行高 | 1.9 |
| 段落間隔 | 本文サイズの1倍（1em） |
| 本文の太さ | 400 |
| 見出しの太さ | 600 |

本文サイズを比較する最初の段階では、最大幅・行高・段落間隔を共通にする。720pxの場合、全角文字の目安は17pxで約42文字、16pxで約45文字となるが、和欧文混在時の実際の行長は書体・文章により変わる。

| 要素 | 本文に対する比率 | 本文17pxの場合 | 本文16pxの場合 |
| --- | ---: | ---: | ---: |
| 記事タイトル | 1.6倍 | 27.2px | 25.6px |
| H2 | 1.4倍 | 23.8px | 22.4px |
| H3 | 1.25倍 | 21.25px | 20px |
| H4 | 1.125倍 | 19.125px | 18px |
| H5 | 1.0625倍 | 18.0625px | 17px |
| H6 | 1倍 | 17px | 16px |

小数は比率からの計算値であり、その精度での固定を求めるものではない。H5とH6が区別しにくくならないかを、実際の文章と周囲の余白を含めて重点確認する。識別しにくい場合は、本文以上のサイズを維持しながら比率・太さ・余白を再調整する。

| サイトタイトル | デスクトップ | モバイル |
| --- | ---: | ---: |
| ホーム | 36px | 30px |
| その他のページ | 24px | 22px |

サイトタイトルは記事内の見出しとは役割が異なるため、別のスケールとする。一覧見出し、メタ情報、UIラベル等の細部は、上記を基準にモックで調整し、共通部品ごとに揃える。

## 配色と面の区別

### 必須ルール

コードのシンタックスハイライトとコード背景は、ライトでCatppuccin Latte、ダークでCatppuccin Mochaを厳密に維持する。サイトの背景・境界線・文字は公式パレットを基本にし、領域の区別やコントラストに必要な範囲で派生色を使ってよい。

コード以外の領域に面分けを増やさず、ページ全体を一枚の背景として構成する。コード領域は背景の穏やかな差に加え、内側余白・細い境界線・小さな角丸で区別する。

### 初期パレット

| 用途 | ライト | ダーク | 扱い |
| --- | --- | --- | --- |
| ページ背景 | `#f8f9fc`（派生色） | `#181825`（Mocha Mantle） | 調整可能 |
| コード背景 | `#eff1f5`（Latte Base） | `#1e1e2e`（Mocha Base） | 固定 |
| 本文 | `#4c4f69`（Latte Text） | `#cdd6f4`（Mocha Text） | 公式色を基本に調整可能 |
| 本文リンク・基本案 | 本文と同色＋下線 | 本文と同色＋下線 | 基本案 |
| 本文リンク・比較版 | `#1e66f5`（Latte Blue）＋下線 | `#89b4fa`（Mocha Blue）＋下線 | 比較項目 |

公式色の出典は[Catppuccin Palette](https://catppuccin.com/palette/)。補助文字・境界線・フォーカス等は公式色を出発点に、背景との区別と全体の階調を確認して選ぶ。[Catppuccin Style Guide](https://github.com/catppuccin/catppuccin/blob/main/docs/style-guide.md)

ライトはコードがページより少し暗く、ダークは少し明るい組み合わせとなる。背景色を全面適用したときと、リンク・コード・画像が多い実記事で見たときの両方を確認する。パレット名だけを根拠に可読性やアクセシビリティへの適合を保証せず、実際の色の組み合わせを評価する。

## 記事詳細と本文部品

### 記事詳細の順序

1. 記事タイトル。
2. 公開日、更新があれば更新日。
3. 任意のカバー画像。
4. 比較版のみ、閉じた状態の目次。
5. 本文。
6. タグ。
7. シェアとはてなスター。
8. 前後記事。

シェア先はX・Facebook・はてなブックマーク。はてなスターはシェアとは別の操作として区別する。いずれも読了後の位置にまとめ、現在のHTML・アイコン・配置をそのまま再現する必要はない。Xのシェアに記事タグ由来のハッシュタグは付けない。

記事ごとの著者名、読了時間、文字数、パンくず、編集リンク、トップに戻るボタンは表示しない。シェアとスターは一覧に出さない。

### コードブロック

- 背景とシンタックスの色は固定したLatte/Mochaを使う。
- 細い境界線、小さな角丸、十分な内側余白を付ける。具体的な寸法は共通部品の初期値としてモックで調整する。
- 文字サイズ14〜15px、行高1.5を初期値とする。日本語コメントや複数行が詰まって見える場合に1.6と比較する。
- 長い行は折り返さず、コードブロック内で横スクロールする。ページ全体の横スクロールにはしない。
- コピーボタンは常時表示し、タッチ操作でも発見できるようにする。成功・失敗の表示を用意する。
- 言語名は指定があれば小さく表示し、ファイル名も必要な場合だけ表示する。
- 行番号は通常表示せず、記事側で指定した場合に対応する。言語なし・行番号あり・強調行ありの状態も確認する。
- 行高とブロックの内側余白を独立して調整する。

インラインコードは同じ等幅フォントとBase色を使う。文章の行高を不自然に押し広げず、日本語に挟まれた識別子や英数字も読みやすくする。

### 本文のその他の部品

| 要素 | 基本案・確認事項 |
| --- | --- |
| リンク | 本文色＋下線。Blue＋下線と比較する。ホバー時にBlueへ変える案も試せるが、通常時の下線とフォーカス表示は維持する |
| 引用 | 細い左罫線と余白。背景色は変えない |
| 表 | 見出し行を太字にし、薄い横罫線で区切る。全セルを囲う罫線や縦罫線は基本案に使わない。狭い画面では表の中で横スクロールする |
| 箇条書き・番号付きリスト | 標準の記号を使い、項目間・入れ子の余白を整える |
| 本文画像 | 元の縦横比を保ち、本文幅以内に表示する |
| キャプション | 画像の下に左揃えで置き、本文より控えめな文字色とサイズにする |
| 脚注 | 本文末にまとめ、参照元へのリンクを用意する |
| 強調・区切り等 | 本文との階調・余白を揃え、長文全体で確認する |

リンクを多用する技術記事で、リンクだけが過度に目立たず、リンクとしても発見できるかを確認する。カード状の囲みや影を増やさず、コード・引用・表の役割が識別できる程度の違いを付ける。

### 目次の比較版

基本モックは目次なし。長い技術記事でのみ、記事冒頭に閉じた折りたたみ式目次を置く比較版を用意する。採用決定はモック比較後に行う。

比較版では開いた状態も確認し、長い日本語見出し・深い階層・見出しへの移動を扱う。一列構成を維持し、サイドバーや画面への固定表示は設けない。

## 記事一覧とカバー画像

### 一覧の基本構成

一記事あたりタイトル・日付・短い要約と、ある場合はカバー画像を表示する。記事同士は余白で区切り、カード枠や影を前提にしない。要約はまず3行を共通にしてカバー配置を比較し、その後に要約の長さと記事間の余白を調整する。

要約の3行は固定上限ではない。文字中心の外観とカバーのバランスが取れるなら、長くすることも検討する。

### 画像の必須ルール

- 最大幅を基準に、元の縦横比を変えずに表示する。
- 高さの上限は設けない。切り抜きや縦横比の統一が必要なら、元のカバー画像側で調整する。
- モックの基準画像は1200×630とし、その比率で調和することを主な評価対象とする。この寸法はモック素材の基準であり、アップロード画像全般への強制条件ではない。
- 画像に枠や影は付けない。カバーなしの記事に空の画像枠を作らない。

例えば1200×630の画像を幅720pxで表示すると高さ378pxとなる。その高さを360pxに制限して幅まで縮める処理は行わない。このルールは記事詳細のカバーにも適用する。

### 比較する配置

| 案・画面 | 配置と初期値 |
| --- | --- |
| デスクトップ・横添え案 | テキストを主にして右側に小さなカバーを添える。画像幅160pxを出発点とし、高さは比率から決まる |
| デスクトップ・全面表示案 | タイトル・日付・要約の下に、本文幅以内でカバーを表示する。高さは比率から決まる |
| モバイル・両案共通 | タイトル・日付・要約の下に、利用可能な幅以内でカバーを表示し、文字の横幅を確保する |

1200×630を幅160pxで表示した場合の高さは84px。横添え案では画像の有無によるテキストの見え方、全面表示案では画像が一覧の主役になりすぎないかを確認する。

## 分類・アーカイブ・404

- タグ・カテゴリ一覧は分類名と件数を並べ、幅に応じて折り返す。塗りつぶしたチップにはしない。
- 個別タグ・カテゴリと記事一覧は、見出しと必要なら説明文を置き、同じ一覧部品を使う。
- Archivesは年→月→記事タイトルと日付の順に整理し、要約・カバーを出さない。
- ページ送りは「前へ」「次へ」と現在ページ／総ページ数を表示する。初ページ・最終ページで存在しない移動先を操作させない。
- 404は「ページが見つかりません」という見出し、短い説明、ホームとArchivesへのリンクを置く。巨大な「404」を主役にしない。

これらの画面も共通のフォント・階調・余白のルールで揃える。

## 操作状態とアクセシビリティ

| 対象 | モックに含める状態・確認 |
| --- | --- |
| リンク・ボタン | 通常、ホバー、キーボードフォーカス。フォーカスには見える輪郭を付ける |
| コードコピー | 通常、成功、失敗。モバイルでもボタンが見つかる |
| 目次比較版 | 閉じた初期状態、開いた状態、見出しへの移動 |
| 配色切り替え | ライト／ダークの二状態。切り替え先が分かるアイコンと読み上げ用ラベル |
| 小画面・拡大 | 本文やナビゲーションを失わずに折り返す。表・コードは必要な範囲で局所的に横スクロール |
| 和欧文・色 | フォントの混在、補助文字、リンク密集、両モードでの可読性・コントラスト |

配色は初回にOS設定へ追従し、操作後は選択したライト／ダークを維持する。システム設定に戻すためのUIは対象外。三状態を巡回するボタンにはしない。

ホバーしないと存在が分からない操作は作らない。タッチ操作とキーボード操作を考慮し、装飾的な動きを最小限にする。モックで状態を表現したことと、完成実装でのアクセシビリティ検証は区別する。

## 比較計画とモックの確認条件

### 基本モックと追加比較

全対象画面は基本案の400px／1280px・両配色で揃える。比較案をすべての画面・幅へ総当たりで展開せず、次の代表画面で比較する。

| 比較項目 | 基本案 | 比較候補 | 代表画面 |
| --- | --- | --- | --- |
| 本文サイズ | デスクトップ17px／モバイル16px | 両方17px、両方16px | 同じ長い技術記事 |
| カバー配置 | 未選定。両案を比較して決める | 横添え、全面表示 | 画像あり・なしが混在するホーム |
| 目次 | なし | 冒頭に閉じた目次 | 同じ長い技術記事 |
| 本文リンク | 本文色＋下線 | Blue＋下線 | リンクを多用する同じ記事 |
| 記事タイトル | 本文の1.6倍 | 必要に応じ約30pxの前案 | 長い日本語タイトルを持つ記事 |
| コードの行高 | 1.5 | 詰まって見える場合に1.6 | 日本語コメント・複数行を含むコード |

カバー配置が決まるまでは、全画面の基本案へ適用する一覧部品を仮選択であると明記する。目次ありを基本案や採用決定として扱わない。本文サイズ比較の最初は幅・行高・段落間隔を揃え、選定後にそれらを再調整する。

### 確認に使う内容

実記事を優先し、足りない状態は部品確認用の文章で補う。長い日本語タイトル、和欧文の混在、H2〜H6、リンクの多い段落、引用、入れ子リスト、表、脚注、インラインコード、コードブロック、日本語コメント、画像とキャプションを含める。

カバーの主比較は1200×630を使う。縦横比の異なる既存画像も収まり確認に使えるが、テーマ側で切り抜いて標準比率へ合わせる要件にはしない。

### モック完了時に残すもの

1. 全対象画面の基本案と、指定した代表画面の比較版。
2. 実際に使ったフォント候補順、文字サイズ比率、行高、余白、色、画像幅等の値。
3. 比較項目ごとの採否または継続検討の記録と、その理由。
4. 320px・360px・768pxでの収まり、および操作状態の確認結果。
5. H5/H6の識別、リンクが多い文章、和欧文の混在、コードとページ背景の調和についての評価。

この文書の作成時点では、モックの制作・比較・表示検証は未実施。上記は今後モックを作る際の要件と確認条件である。
