## 成果物と実記事

`mock/site/`に34画面とレビュー入口を収録。共通CSS・JavaScriptを利用し、同じHTMLを各幅・配色で表示する。記事の本文や一覧は静的HTMLに含まれる。

| 対象 | 成果物 |
| --- | --- |
| ホーム・ページ送り | `home.html`、`home-2.html`、`home-3.html` |
| 記事詳細 | `article.html`ほか実記事5件。カバーあり・なし、長文・短文、タグなしを含む |
| About | `about.html`。既存プロフィール全文と全SNSリンク。記事用メタ情報は付けない |
| 記事一覧 | `posts.html`、`posts-2.html`、`posts-3.html` |
| タグ・カテゴリ一覧 | `tags.html`、`categories.html` |

| Archives・404 | `archives.html`、`404.html` |
| 0件・1件・要約なし | `empty.html`、`single-item.html` |

基準記事は「2026年、開発環境を一新した。Ghostty、herdr、Neovim、mise、そして自作Zshプロンプト」。1200×630のカバー、本文画像・動画も元データを使用した。「HugoとCloudflare Pagesでブログを作り直した」と短い日記3件を加え、一覧やArchivesに異なる文量を含めた。本文に足りない要素は、実記事を改変せず部品確認用文章で補った。

Hugoはビルド時のMarkdown・shortcode変換とChromaのCSS生成にだけ使う。実行時はHTML/CSS/JavaScriptのみ。本番のHugo設定・PaperModには依存しない。

## 比較結果と継続検討

以下はモック制作者による所見。ユーザーによる最終選定を代行するものではない。すべての比較候補をレビュー入口から開ける。

| 項目 | モック時点の扱い・所見 |
| --- | --- |
| 本文サイズ | 17px／16pxを基本として維持。17px統一はモバイルで文字を大きく読める分、同じ段落の縦方向が長くなる。16px統一はデスクトップで一行の情報量が増える。最終採否は継続検討 |
| 一覧カバー | 横添えを仮選択。文字中心の一覧に馴染む一方、コードのスクリーンショットの内容までは読めない。全面版は内容を認識しやすいが、1記事が占める縦幅が大きい。両案を残す |
| 目次 | 基本案には採用しない。開閉と移動は有用だが、深い階層の目次は320pxで縦に長くなる。長文用比較として継続検討 |
| 本文リンク | 本文色＋下線を基本として維持。リンクの多い段落でも文として追いやすく、下線で発見できる。Blue版は参照先が目立つため、強調量の好みを比較できる |
| 記事タイトル | 本文の1.6倍を維持。長い和欧混在タイトルでも本文との強弱を保つ。30px版も比較可能だが、特にモバイルで占有面積が増える |
| コード行高 | 14px／1.5を基本として維持。日本語コメントを含むコードも読め、1.6はもう少しゆったりする。実フォントによる差を今後も確認する |
| H5とH6 | モバイルで17px／16px、太さ600。本文との区別はできるが、相互の差は小さい。比率は維持し、ユーザーの目視選定事項として明示的に残す |
| 和欧文 | macOSのChromeで文字化け・欠落・不自然な段落行間は見られなかった。英数字を含む本文、見出し、日本語コメントを目視した。実際に各字形へ使われたフォント名の特定や別OSの実機確認はしていない |
| ページとコード | 背景差は穏やかだが、細い境界・内側余白を加えて領域を識別できる。色の強い面をコード以外に増やさない構成を維持 |

目視後、Aboutはプロフィールを先に置き、SNSリンクを折り返す一覧にした。比較操作の検証で見つかった「17px統一案がモバイルの基本16pxに上書きされる」問題を修正し、再測定で17pxになることを確認した。

## Chromeでの検証

ユーザーが指定したChromeをChromeコントロール経由で操作した。本文とコードのフォント候補順・計算済みサイズを測定し、実際の描画を目視した。外部のブラウザ自動化や別ブラウザへの置き換えは行っていない。

### レイアウト

- 全34画面を400px／1280px・ライト／ダークで巡回。ページ全体の横はみ出し、ナビ・タイトル・本文・画像・表領域・コード領域の画面外へのはみ出し、画像読み込みを検査。
- 320px・360px・768pxでも追加確認。本文を縮小画像のように扱わず、幅に応じて折り返す。
- 320pxではナビの配色ボタンが2行目に回る。リンクや操作を非表示にはしない。
- コードと幅広い表は局所的に横スクロールする。キーボードの右矢印でそれぞれ40px動き、ページの`scrollX`は0のまま。
- 1200×630画像は、デスクトップ横添えで160×84px、全面表示で720×378px。高さ上限による幅の縮小はない。
- 400px表示のスクロールバーあり環境では、利用可能幅が385px、本文幅が345pxになる。スクロールバーなしでは本文幅360px。寸法を一律に360pxと仮定しない。
- 幅320pxは1280pxの400%拡大時に相当するリフロー幅としても確認した。Chromeのネイティブズームショートカットは操作APIから倍率変化を確認できなかったため、実際の200%／400%倍率操作を検証済みとは扱わない。通常のChromeでの手動ズームは可能。

ホーム・記事・About・分類・個別カテゴリ・Archives・404・本文部品をスクリーンショットで目視し、目次展開・リンクフォーカス・コードコピーの表示も確認した。Chromeコントロールの画面幅変更直後にスクリーンショットが縮小される場合があったため、表示領域を再設定し、等倍で判断できる状態で再確認した。

### 操作

| 操作 | 確認結果 |
| --- | --- |
| 内部リンク | ホームから記事、目次からH6へ移動。目次の移動後は対象見出しが上端から約24pxに表示 |
| 配色 | ライト／ダーク切り替え、切り替え先の読み上げラベル、保存した選択の再読み込み |
| OS追従 | 初期値・設定後の優先順位・OS変更・保存不可環境をJavaScriptの単体テストで確認。OSそのものの設定は変更していない |
| コピー成功 | コピーボタンを操作し、成功表示を確認。行番号付きTOMLをレビュー入口へ貼り付け、行番号なし・改行維持の内容と一致 |
| コピー失敗 | 専用条件で失敗を再現。「再試行」と手動選択の案内を表示 |
| 目次 | 閉じた初期状態、キーボードで開閉、深い階層、アンカー移動 |
| ホバー | 本文色`rgb(76,79,105)`からBlue`rgb(30,102,245)`へ変化し、下線は維持 |
| フォーカス | Tab操作後のリンクにBlue・2pxの輪郭と4pxの間隔を確認 |
| ページ送り | 初・途中・最終ページを用意し、存在しない前後の移動はリンクにしない |
| シェア・スター | 3サービスそれぞれのローカルな表示フィードバック。スターの選択表示。外部送信なし |

初版の生のレイアウト測定結果は[検証データ](../mock/verification/browser-checks-v1.json)に保存する。幾何情報の検査は目視の代替ではなく、全画面・全幅の共通不具合を見つけるための補助として使った。

## 自動検査と限界

```sh
node mock/build.mjs
node mock/verify.mjs
node mock/test-theme.mjs
```

HTML35件、内部参照487件、アンカー、画像alt、重複ID、記事情報の順序、Aboutの省略要素、空状態、目次、コードの特殊状態、公式Base色、1200×630画像を検査する。配色の状態遷移は別途単体テストする。

このモックは、実サービスのシェア・はてなスター連携、SEO、性能、全記事移行、Windows／Android／iOSでの実機フォント確認、スクリーンリーダーを使った網羅的試験、WCAG適合性判定までは行わない。特にCatppuccinの公式トークン色を維持したことだけで、すべてのコード文字色のコントラスト適合を保証しない。
