# 12. 相対サイズへの移行

2026-09-08、第8案。[現行要件](04-theme-visual-requirements.md)と[HTMLモック](../mock/README.md)に反映済み。フォントは確定済みの指定を変更しない。Safariのui-monospaceによるSF Mono（.AppleSystemUIFontMonospaced）の適用はユーザーが確認済み。

## 採用した方針

ブラウザの既定文字サイズを起点に、モバイルは100%、640px以上では106.25%をルートに指定する。本文は1remとし、見出しや補助文字もルートに対する共通比率で定義する。

```css
html { font-size: 100%; }
@media (min-width: 640px) {
  html { font-size: 106.25%; }
}
body { font-size: 1rem; }
h1 { font-size: 1.6rem; }
.site-name { font-size: 2rem; }
.code-block pre { font-size: 0.875rem; line-height: 1.5; }
```

以下のpx値はブラウザの既定文字サイズが16pxの場合だけの換算値。固定値ではない。

| 対象 | 指定 | デスクトップ | モバイル |
| --- | --- | ---: | ---: |
| 本文 | 1rem | 17px | 16px |
| 記事タイトル | 1.6rem | 27.2px | 25.6px |
| サイトタイトル | 2rem | 34px | 32px |
| コードブロック | 0.875rem | 14.875px | 14px |
| 本文内インラインコード | 0.85em | 14.45px | 13.6px |

H2〜H6は1.4／1.25／1.125／1.0625／1rem。記事タイトル×1.25がサイトタイトルとなり、全体の階層が同じルートに連動する。bodyだけで17px相当にする方法も可能だが、このモックではルートを揃えることで大小画面間の比率を共通化する。

## 単位の使い分けと移行時の変化

- 文字サイズ、ヘッダー・一覧・コード領域の余白、操作部品の最小寸法・アイコンは原則rem。
- インラインコードの文字サイズ・padding、段落や本文見出しの余白、リストの字下げなど、周囲の文字に追従させる部分はem。インラインコードは0.85emと上下0.25em・左右0.35emを維持する。
- 行高は単位なし。本文1.9、コード1.5を維持する。
- 本文の最大幅720pxは変更しない。左右ガター24px／20px、切り替え幅640px、罫線・輪郭・角丸はpxのまま。画像は流動幅で縦横比を維持する。
- 従来の補助文字12／13／14／15pxは0.75／0.8125／0.875／0.9375remに統一。従来pxの余白も16で割ったremを基本にする。そのため既定16pxのデスクトップでは、これらは従来比6.25%大きくなる。例：ヘッダー上余白64px→4rem＝68px。本文やサイト名の基準サイズは維持する。
- 配色ボタンは固定heightをやめ、min-heightにする。コードツールバーはラベルとコピーを折り返せるようにし、長い失敗表示でも切らない。ページ送り・アーカイブの列も縮められるようにする。
- 一覧の要約3行省略は従来どおりの意図した抜粋。記事本文や操作の欠落と区別する。

ブラウザの既定文字サイズを20pxにした場合、仕様上は本文20px／21.25px、32pxなら32px／34pxになる（モバイル／デスクトップ）。相対指定だけでアクセシビリティ適合を保証せず、拡大時の折り返し・操作性を別途検証する。[W3Cの相対サイズの説明](https://www.w3.org/WAI/tutorials/page-structure/styling/)、[文字サイズ変更の解説](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)

## 検証

- 全33ページを再生成。静的検査416ローカル参照、配色状態、コードコピー成功／失敗／再試行のテストに合格。静的検査にはルート割合、各rem比率、font-sizeのpx禁止、固定高さ回帰、検証用CSSの残留防止を追加。
- Chromeで全33画面×5幅（320・360・400・768・1280px）×両配色＝330条件を確認。
- 追加で代表10画面×4幅（320・400・768・1280px）×両配色×文字1.25倍／2倍＝160条件を確認。対象は入口・ホーム・実記事・About・記事一覧途中ページ・Tags・Categories・Archives・404・本文部品。
- 合計490条件でページの横あふれ、確認対象要素の画面外配置、ボタン・ナビ文字の切れ、読み込み済み画像の欠落は検出されなかった。本文・タイトル・サイト名・コードの計算後サイズも比率と一致（丸め誤差の許容0.001）。
- 320px・文字2倍で実際にコピー失敗を操作し、Copy failedが欠けず、ツールバーが縦に伸びる表示を確認。通常400pxの記事も目視確認した。
- インラインコードの行高は文字2倍でも60.8px。320pxではpaddingの有無で折り返し位置と段落全体の高さが変わるため、段落の高さの差をそのまま行高の増加とは扱わない。

### 検証の限界と再現方法

エージェントによる検証では、ブラウザ設定画面が操作制限で開けず、既定文字サイズを実際に変更した試験は未実施。代わりに一時的なビルドでルートの割合を1.25倍／2倍にした。ブラウザ設定の代用によるレイアウト負荷試験であって、実設定への追従をエージェントが実測したものではない。その後、ユーザーからブラウザのフォントサイズ変更も検証できたとの報告を受けた。ブラウザ名・設定値などの詳細は未記録。ネイティブズームや他OS・他ブラウザの網羅的な描画検証とは区別する。

```sh
node mock/build.mjs --text-scale=1.25
node mock/build.mjs --text-scale=2
# 確認後は通常ビルドへ必ず戻す
node mock/build.mjs
node mock/verify.mjs
```

検証オプションはmock/site/を一時的に上書きし、HTMLにdata-text-scale-test付きstyleを追加する。ブラウザ設定・保存済み配色は変更しない。生成物は通常ビルドへ復帰済み。実ブラウザでの追加確認時は既定文字サイズを20px／32pxへ変更し、本文・見出しの比率、320px相当のリフロー、表・コードの局所スクロールを確認する。設定は試験後に元へ戻す。[W3Cのリフロー解説](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)
