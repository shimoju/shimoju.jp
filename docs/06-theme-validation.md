# 6. テーマ実装の検証手順

[視覚要件](04-theme-visual-requirements.md)と[実装上の判断理由](05-theme-implementation.md)を満たすか確認する。モックの検査と本番テーマの受け入れ検査は分ける。

## 自動検査

リポジトリ直下から実行する。モックの再生成にはHugo、検査にはNode.jsが必要。

```sh
node mock/build.mjs
node mock/verify.mjs
node mock/test-theme.mjs
node mock/test-copy.mjs
node mock/test-sharing.mjs
```

| 検査 | 実装に引き継ぐ観点 |
| --- | --- |
| verify.mjs | リンク・アンカー・画像alt・重複ID・H1、記事情報の順序、Aboutの表示項目、一覧端・空状態、ホームのAbout重複防止、カバー比率、フォント候補・palt、rem比率、公式Base色 |
| test-theme.mjs | OS初期配色、明示選択と保存の優先順位、OS変更、保存不可環境。レビュー入口の配色同期・CSS読み込み後のフォント候補表示はモック用 |
| test-copy.mjs | コピー対象の文字列、行番号除去、空白・改行、3秒後の復帰、連続コピー、拒否・失敗・再試行 |
| test-sharing.mjs | 公開URL・日本語タイトルのエンコード、記事・Aboutの共有先、スターのみの読み込み・重複防止、エラー通知、一覧・レビュー等での非接続 |

モックの収録画面は[モックREADME](../mock/README.md#収録画面とソース)を参照する。スクリプトの検査はブラウザの描画・実際のクリップボードへの貼り付け・アクセシビリティの適合性評価を代替しない。

## 画面と操作の確認

基本は全対象画面を400px／1280px・ライト／ダークで確認する。追加の320px・360px・768pxではナビ、長いタイトル、本文、画像、表、コード、ページ送りの収まりを重点確認する。

| 対象 | 確認すること |
| --- | --- |
| 共通枠 | 中央のサイト名・ナビが折り返す。ページ全体に横スクロールが出ない。ヘッダーは固定しない |
| ホーム・一覧 | 紹介はホーム初ページのみ。画像・タイトル・日付・要約が一つのリンク。0件・1件・先頭／途中／最終ページ、要約なしでも成立する |
| About | 記事と共通の日付表示・更新日判定、シェア・はてなスターがある。共有・スターの対象は公開About URL。タグ・前後記事はない。現行本文を使う |
| 分類・Archives・404 | 分類名と件数、年月と日付、復帰導線が読める。記事が少ない場合も不要なページ送りを表示しない |
| 本文 | H2〜H6の階層、H5／H6の区別、和欧文・長いURL・リスト・引用・脚注。リンクは本文色＋下線 |
| 画像 | 1200×630を基準に、幅720pxなら高さ378px。ほかの比率も切り抜かず、高さ上限で縮めない。本文画像と動画も確認 |
| 表・コード | 表は横罫線中心。長い行は領域内で横スクロールでき、ページ全体は動かない。キーボードでもスクロール可能 |
| コピー | 言語・ファイル名あり／なし、未知の言語、行番号・強調行。コピー後に貼り付けて原文と照合し、失敗後に再試行する |
| フォーカス | Tab順序、リンク全体の輪郭、配色ボタンの読み上げ名。ホバーだけに依存せず、要素を拡大しても輪郭が切れない |
| 配色 | 初回OS追従、明示切り替え、再読み込み、OS変更、ストレージ無効。本文とコードを同じモードで描画し、ちらつかない |

コード本文と言語ラベルの左端が揃い、本文左右paddingが16px相当であること、ナビ横gapが24px／16px相当、タグ横gapが8px相当、記事末尾タグ・分類一覧の左右paddingが4px相当、ガターが24px／16pxであることを確認する。角丸は大8px・小4px、絵柄は20px／24px相当とし、本文スケールとインラインコードの組版は維持する。

操作部品は最小高さ4.8rem、ページ送り・アイコンは最小幅も4.8remを確認する。ヘッダーナビ・タグ／カテゴリは自然幅で、短いラベルの文字間隔、対象同士の重なり、狭い幅での折り返しを確認する。文字拡大時にテキスト操作部品の高さが伸びること、本文内リンクと公式スターに寸法を強制していないことも確認する。

スクリーンショットの目視とDOM寸法の確認を併用する。全画面の寸法が範囲内でも、読みやすさや文字色のコントラストが保証されるわけではない。

## 見出し余白と補助文字

補助文字3段階（本文の0.910／0.829／0.754倍）と一覧タイトル1.207倍、本文画像・表・コードの前後余白1.931emを確認する。ナビはモバイルも本文の0.910倍とし、320pxで折り返しと操作領域を確認する。

本文内のH2〜H6が前2.121em・後0.687emで共通化され、記事タイトルには影響しないことを確認する。本文先頭要素の上余白0、連続見出し・段落・表・コードとのマージン相殺を確認し、CSSの余白値と実際の空白を区別する。

## コンテンツ・更新日・フィード

### モバイルの前後記事ナビゲーション

レビュー入口の代表ページ「前後記事あり」「長い実記事・Nextのみ」「Previousのみ」を使う。

前後記事は全画面幅で左右同幅の横並びとし、列間はデスクトップ24px・639px以下では16px。新しい記事へのPreviousを左、古い記事へのNextを右に固定し、一覧のページ送りと時系列を揃える。片方だけでも位置を維持し、長いタイトルは切り詰めず折り返す。320px／400px・両配色で、長いタイトルの行数、操作範囲、左右の判別性を確認する。

ページ送りと前後記事のラベルは`« Previous`／`Next »`で共通。記号と文字の間隔を実画面で確認し、前後記事では記事タイトルだけにホバー下線が付くことも確認する。

ホームの紹介文が現行Hugo設定と一致し、2ページ目以降には表示されないこと、Aboutが現行本文から生成されることを確認する。更新日は`.Date`と`.Lastmod`の表示上の年月日が異なる場合だけ表示する。dateのみ指定して補完された場合・同日時指定・同日の時刻差では非表示、別日なら表示、更新日がゼロ時刻なら非表示を確認する。公開日・更新日の横gapは1.6rem、タグの横gapは0.8remを確認する。記事詳細・About・一覧・Archivesのタイトルと日付の間隔は0.8rem。Archivesではmargin値だけでなく、タイトルと日付の行ボックス間が8px相当であることを実測する。月名と先頭記事のベースライン、長いタイトルの折り返し、タイトルだけのホバー下線、日付を含むリンク全体のフォーカスを確認する。記事間24px・月間32pxで、最終項目に余白が重ならないことも確認する。分類一覧は件数を除いて分類名だけにホバー下線が付くことを確認する。前後記事は両方あり・Previousのみ・Nextのみの各状態でデスクトップの左右位置が変わらず、モバイルでも左右同幅の2列・列間16pxになることを確認する。

本実装ではHugo標準の名称順、1ページ10件、各RSS（home/section/taxonomy/term）の既存URL・対象範囲・要約・無制限・自動検出を確認する。画面上の更新日表示条件がRSS・OGP・構造化データの日付出力に影響しないことも検査する。カバーなし記事にOGP画像を出さない。外部埋め込みの実動作は本実装時に検証する。

## フォント・palt

本文・記事見出し・サイト名はApple標準＋Segoe UIを共用する。コードはMenlo → Consolas → monospaceを確認し、和文候補は明示しない。ブラウザの「実際に描画されたフォント」とCSSの候補リストを区別する。

- MacのSafari／Chrome／Firefox：本文のSan Franciscoとヒラギノ、サイト名300と本文400／見出し500／強調700の階層と記号類を確認。コードは欧文Menloと、日本語コメントのフォールバック・字幅を確認。
- Windows：本文のSegoe UI＋Noto、サイト名300と見出し500の実フェイス、本文400との差を確認。コードは欧文Consolasと、ブラウザが選ぶ和文コード書体の字幅・鮮明さを確認。本文のNotoあり／なしとは分けて検証する。候補が存在するだけで良好な描画を保証しない。
- Linux／Android：Menlo・Consolasがない環境でも、コードの欧文iiii／WWWW／0000が等幅になることを確認。Noto Sans CJK JPだけが導入された環境も対象とする。和文は本文との一致ではなく、字幅と読みやすさで評価する。
- iOS／Android：日本語フォールバック、本文・インラインコードのベースライン、長文と小画面での可読性を確認。特にiPhone Safariはルート62.5%・本文1.7remで和文が読みやすくなるか確認し、コードの14px相当・行高1.3で日本語コメントや強調行が詰まりすぎないか確認する。
- palt：入口の同一文で有効／無効の差を確認。コードに継承しないことも確認する。
- インラインコード：文字と背景の余裕、行送り、隣接行の背景の接触を確認。paddingによる折り返しの増加は行高増加と区別する。

必要なら対象端末のフォントファイルを明示し、再検査する。インストールやWeb配信は不要。

```sh
node mock/inspect-fonts.mjs /path/to/font.ttf /path/to/font.ttc
```

このツールは名前、版、GPOS／GSUB、アウトライン・ビットマップテーブル、名目送り幅を読む。実際のブラウザ選択・シェーピング・可変軸全体の描画は検査しない。

## 文字サイズとズーム

ブラウザの既定文字サイズを16px・20px・32pxに変え、元の設定へ戻せるよう値を控える。期待する本文サイズは次のとおり。

| 既定文字サイズ | 本文：ルート62.5%・1.7rem | コードブロック：1.4rem |
| --- | ---: | ---: |
| 16px | 17px | 14px |
| 20px | 21.25px | 17.5px |
| 32px | 34px | 28px |

H6→H1のサイズは本文の1、1.099、1.207、1.326、1.456、1.6倍とし、丸め前の倍率`1.6^(1/5)`に基づく5区間の階層を確認する。見出しのem指定の余白も拡大するため、長い見出し・連続する見出し・段落とのマージン相殺を確認する。記事タイトルは本文の1.6倍、サイト名は1.931倍。コードは本文基準トークンと独立した1.4remとする。本文基準を変更した場合に、見出しとモジュラースケールの余白だけが追従し、コード・独立UIの寸法が変わらないことも確認する。この表はCSSの計算サイズであり、Safariの和文の見た目上の縮小とは区別する。コード行高は1.3（標準設定で18.2px）。本文最大幅720pxは変えずに折り返す。固定高さによる文字・ボタンの切れがないか確認する。

ネイティブの200%ズーム、1280pxを400%にした320 CSS px相当のリフローも別に確認する。viewport幅変更、既定文字サイズ変更、ブラウザズームは同じ試験ではない。[W3C Resize Text](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)、[Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)

レイアウト負荷を手早く再現する場合だけ、次の一時ビルドを使う。

```sh
node mock/build.mjs --text-scale=1.25
# 各画面を確認する
node mock/build.mjs --text-scale=2
# 確認後、必ず通常ビルドへ戻す
node mock/build.mjs
node mock/verify.mjs
```

これはmock/site/を一時的に上書きしてルートの割合を拡大する検証であり、ブラウザ設定を変更するものではない。verify.mjsは検証用styleの残留をエラーにする。

## 確認済みの範囲と本実装で残る確認

CopyからTabでコード本文へ移動し、フォーカス枠の四辺が内側に見え、矢印キーでコードを横スクロールできることを確認する。動画の前後余白は本文基準1.931em、Archivesの日付は本文の0.829倍。短いCategoriesと長いArchivesの往復で、通常型スクロールバーが出入りしても本文とサイト名が横移動しないことを確認する。

本文部品の組み合わせ見本で、引用内のリスト・コード、複数段落と入れ子リストを含む項目の余白・字下げ・局所スクロール・フォーカスを検証する。定義リストとdetails/summaryは今回の対応追加には含めない。

モックの自動テストと、macOS Chromeの主要画面・両配色・狭い幅・文字拡大は確認済み。WindowsでのSegoe UIの300・500、iPhone Safariの本文・コードの可読性、ブラウザの既定文字サイズ変更はユーザー確認済み。フォントの実測結果と注意点は[実装上の判断理由](05-theme-implementation.md)を参照する。ブラウザ版・設定の網羅的な記録はないため、全対象環境の検証を代替しない。

a要素のtext-underline-offsetは0.26emとする。Windows実機で和文・欧文の下線位置、複数行リンク、ホバー時の下線を確認する。SVGアイコンリンクには下線を付けない。

Chrome・Firefoxでは通常時・ホバー時・現在地表示の計算済み`text-decoration-thickness`が1pxであることを確認する。対象はヘッダーナビ、ページ送り、記事末尾タグ、本文・脚注のリンク、一覧・前後記事・Archivesのタイトル、分類名。下線は必要な要素だけに現れ、日付・件数・前後記事の方向ラベル・アイコンには付かないことを確認する。100%と拡大表示で太さを比較する。自動検証では`text-decoration`一括指定の混入と、下線を描く要素への太さ指定漏れを検出する。

下線の1px指定と対象別のホバー表示はChromeで確認済み。Firefoxでも意図した太さで表示されることをユーザー確認済み。

本実装では次を確認する。

- Windows・iOS・Android・Firefox等の実機描画、日本語混植、スクリーンリーダー、コントラスト、ネイティブズーム。
- ページ背景と本文・補助文字・リンク・操作部品のコントラストを評価する。コードブロックのシンタックスハイライトは公式Catppuccin配色を維持し、このコントラスト調整の対象外とする。
- JS無効でも本文・一覧・通常リンクを利用できること。コピー・配色ボタンの利用不可状態を適切に扱うこと。
- シェア・はてなスターの[実動作確認](07-theme-sharing.md#検証)に従い、通信・追跡防止・レイアウト変動を確認する。本文中のX等の埋め込みはモックでは未接続のため、本実装で別途確認する。
- 実際のHugoテンプレートで全記事・一覧・分類・ページ送りを生成し、既存URL、画像・動画、RSS、canonical・OGP・JSON-LD、公開環境とプレビューの違いを確認する。
- 性能は[移行時の確認](03-papermod-analysis.md#性能の確認)に従って本番相当の内容で測定する。モックのページ数・ファイルサイズだけで性能やWCAG適合を判定しない。
