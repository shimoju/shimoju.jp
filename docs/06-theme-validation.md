# 6. テーマ実装の検証手順

採否の比較ではなく、[視覚要件](04-theme-visual-requirements.md)と[実装上の判断理由](05-theme-implementation.md)を満たすか確認する。モックの検査と本番テーマの受け入れ検査は分ける。

## 自動検査

リポジトリ直下から実行する。モックの再生成にはHugo、検査にはNode.jsが必要。

```sh
node mock/build.mjs
node mock/verify.mjs
node mock/test-theme.mjs
node mock/test-copy.mjs
```

| 検査 | 実装に引き継ぐ観点 |
| --- | --- |
| verify.mjs | リンク・アンカー・画像alt・重複ID・H1、記事情報の順序、Aboutの省略項目、一覧端・空状態、ホームのAbout重複防止、カバー比率、フォント候補・palt、rem比率、公式Base色 |
| test-theme.mjs | OS初期配色、明示選択と保存の優先順位、OS変更、保存不可環境。レビュー入口の配色同期・CSS読み込み後のフォント候補表示はモック用 |
| test-copy.mjs | コピー対象の文字列、行番号除去、空白・改行、3秒後の復帰、連続コピー、拒否・失敗・再試行 |

現在の生成物はレビュー入口を含む33ページ、検査対象のローカル参照は416件。これらはモックの収録数であり、本番のページ数や性能目標ではない。スクリプトの検査はブラウザの描画・実際のクリップボードへの貼り付け・アクセシビリティの適合性評価を代替しない。

## 画面と操作の確認

基本は全対象画面を400px／1280px・ライト／ダークで確認する。追加の320px・360px・768pxではナビ、長いタイトル、本文、画像、表、コード、ページ送りの収まりを重点確認する。

| 対象 | 確認すること |
| --- | --- |
| 共通枠 | 中央のサイト名・ナビが折り返す。ページ全体に横スクロールが出ない。ヘッダーは固定しない |
| ホーム・一覧 | 紹介はホーム初ページのみ。画像・タイトル・日付・要約が一つのリンク。0件・1件・先頭／途中／最終ページ、要約なしでも成立する |
| About | 記事用日付・タグ・シェア・スター・前後記事がない。プロフィールの全リンクを利用できる |
| 分類・Archives・404 | 分類名と件数、年月と日付、復帰導線が読める。記事が少ない場合も不要なページ送りを表示しない |
| 本文 | H2〜H6の階層、H5／H6の区別、和欧文・長いURL・リスト・引用・脚注。リンクは本文色＋下線 |
| 画像 | 1200×630を基準に、幅720pxなら高さ378px。ほかの比率も切り抜かず、高さ上限で縮めない。本文画像と動画も確認 |
| 表・コード | 表は横罫線中心。長い行は領域内で横スクロールでき、ページ全体は動かない。キーボードでもスクロール可能 |
| コピー | 言語・ファイル名あり／なし、未知の言語、行番号・強調行。コピー後に貼り付けて原文と照合し、失敗後に再試行する |
| フォーカス | Tab順序、リンク全体の輪郭、配色ボタンの読み上げ名。ホバーだけに依存せず、要素を拡大しても輪郭が切れない |
| 配色 | 初回OS追従、明示切り替え、再読み込み、OS変更、ストレージ無効。本文とコードを同じモードで描画し、ちらつかない |

スクリーンショットの目視とDOM寸法の確認を併用する。全画面の寸法が範囲内でも、読みやすさや文字色のコントラストが保証されるわけではない。

## 見出し余白と補助文字

補助文字3段階（0.910／0.829／0.754rem）と一覧タイトル1.207rem、本文画像・表・コードの前後余白1.931emを確認する。モバイルのナビも0.910remへ拡大したため、320pxで折り返しと操作領域を確認する。

本文内のH2〜H6が前2.121em・後0.687emで共通化され、記事タイトルには影響しないことを確認する。本文先頭要素の上余白0、連続見出し・段落・表・コードとのマージン相殺を確認し、CSSの余白値と実際の空白を区別する。選択UIは撤去済みで、古いheading-spaceパラメーターにかかわらず確定値を適用する。

## フォント・palt

本文・記事見出し・サイト名はApple標準＋Segoe UIを共用する。コードはMenlo → Consolas → monospaceを確認し、和文候補は明示しない。ブラウザの「実際に描画されたフォント」とCSSの候補リストを区別する。

- MacのSafari／Chrome／Firefox：本文のSan Franciscoとヒラギノ、サイト名300と本文400／見出し500／強調700の階層と記号類を確認。コードは欧文Menloと、日本語コメントのフォールバック・字幅を確認。
- Windows：本文のSegoe UI＋Noto、サイト名300と見出し500の実フェイス、本文400との差を確認。コードは欧文Consolasと、ブラウザが選ぶ和文コード書体の字幅・鮮明さを確認。本文のNotoあり／なしとは分けて検証する。候補が存在するだけで良好な描画を保証しない。
- Linux／Android：Menlo・Consolasがない環境でも、コードの欧文iiii／WWWW／0000が等幅になることを確認。Noto Sans CJK JPだけが導入された環境も対象とする。和文は本文との一致ではなく、字幅と読みやすさで評価する。
- iOS／Android：日本語フォールバック、本文・インラインコードのベースライン、長文と小画面での可読性を確認。特にiPhone Safariはルート106.25%で和文が読みやすくなるか確認し、コードの14px相当・行高1.3で日本語コメントや強調行が詰まりすぎないか確認する。
- palt：入口の同一文で有効／無効の差を確認。コードに継承しないことも確認する。
- インラインコード：文字と背景の余裕、行送り、隣接行の背景の接触を確認。paddingによる折り返しの増加は行高増加と区別する。

必要なら対象端末のフォントファイルを明示し、再検査する。インストールやWeb配信は不要。

```sh
node mock/inspect-fonts.mjs /path/to/font.ttf /path/to/font.ttc
```

このツールは名前、版、GPOS／GSUB、アウトライン・ビットマップテーブル、名目送り幅を読む。実際のブラウザ選択・シェーピング・可変軸全体の描画は検査しない。

## 文字サイズとズーム

ブラウザの既定文字サイズを16px・20px・32pxに変え、元の設定へ戻せるよう値を控える。期待する本文サイズは次のとおり。

| 既定文字サイズ | 本文：全幅106.25% | コードブロック：全幅14/17rem |
| --- | ---: | ---: |
| 16px | 17px | 14px |
| 20px | 21.25px | 17.5px |
| 32px | 34px | 28px |

H6→H1のサイズは1、1.099、1.207、1.326、1.456、1.6remとし、丸め前の倍率`1.6^(1/5)`に基づく5区間の階層を確認する。見出しのem指定の余白も拡大するため、長い見出し・連続する見出し・段落とのマージン相殺を確認する。記事タイトルは本文の1.6倍、サイト名は1.931倍、コードは14/17倍を維持する。この表はCSSの計算サイズであり、Safariの和文の見た目上の縮小とは区別する。コード行高は1.3（標準設定で18.2px）。本文最大幅720pxは変えずに折り返す。固定高さによる文字・ボタンの切れがないか確認する。

ネイティブの200%ズーム、1280pxを400%にした320 CSS px相当のリフローも別に確認する。viewport幅変更、既定文字サイズ変更、ブラウザズームは同じ試験ではない。[W3C Resize Text](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)、[Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)

レイアウト負荷を手早く再現する場合だけ、次の一時ビルドを使う。

```sh
node mock/build.mjs --text-scale=1.25
# 各画面を確認する
node mock/build.mjs --text-scale=2
# 確認後、必ず通常ビルドへ戻す
node mock/build.mjs
node mock/verify.mjs
```

これはmock/site/を一時的に上書きしてルートの割合を拡大する検証であり、ブラウザ設定を変更するものではない。verify.mjsは検証用styleの残留をエラーにする。

## 確認済みの範囲と本実装で残る確認

モックでは上記自動テスト、macOS Chromeの主要画面・両配色・狭い幅と文字拡大によるレイアウトを確認済み。ブラウザの既定文字サイズ変更、Windowsの通常版Segoe UIで500がSemiboldとなること、Safari／iPhone SafariでApple標準の和文が小さく見えることはユーザー確認済み。モバイル本文拡大・コード行高変更後のiPhone Safariでの表示も、2026-09-10にユーザーが良好と確認した。コードの実書体と混植の字幅は、Safariを含む各環境で別途確認する。サイトタイトルの300についてもWindowsでの適用をユーザーが確認済み。ユーザー確認のブラウザ版・設定値などの詳細は記録されていないため、全対象環境を検証済みとは扱わない。

Windowsでリンクの下線が文字に重なるとの報告を踏まえ、a要素と同様の下線を持つシェアボタンのtext-underline-offsetを0.26emに揃えた。変更後はWindows実機で和文・欧文の下線位置、複数行リンク、ホバー時の下線を確認する。

本実装では次を確認する。

- Windows・iOS・Android・Firefox等の実機描画、日本語混植、スクリーンリーダー、コントラスト、ネイティブズーム。
- Catppuccinの公式色を使うことと、全トークンがコントラスト要件を満たすことは別。背景・文字色の組み合わせで評価する。
- JS無効でも本文・一覧・通常リンクを利用できること。コピー・配色ボタンの利用不可状態を適切に扱うこと。
- モックでは未接続のシェア・はてなスター、X等の外部埋め込みについて、通信・失敗・レイアウト変動を確認する。
- 実際のHugoテンプレートで全記事・一覧・分類・ページ送りを生成し、既存URL、画像・動画、RSS、canonical・OGP・JSON-LD、公開環境とプレビューの違いを確認する。
- 性能は[移行時の確認](03-papermod-analysis.md#性能の確認)に従って本番相当の内容で測定する。モックのページ数・ファイルサイズだけで性能やWCAG適合を判定しない。
