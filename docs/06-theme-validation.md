# 6. テーマ実装の検証手順

[視覚要件](04-theme-visual-requirements.md)と[実装上の判断理由](05-theme-implementation.md)を満たすか確認する。モックの検査と本番テーマの受け入れ検査は分ける。

## 自動検査

リポジトリ直下から実行する。モックの再生成にはHugo、検査にはNode.jsが必要。

```sh
node mock/build.mjs
node mock/verify.mjs
node mock/test-theme.mjs
node mock/test-copy.mjs
node mock/test-sharing.mjs
```

| 検査 | 実装に引き継ぐ観点 |
| --- | --- |
| verify.mjs | リンク・アンカー・画像alt・重複ID・H1、記事情報の順序、Aboutの表示項目、一覧端・空状態、ホームのAbout重複防止、カバー比率、フォント候補・palt、rem比率、公式Base色 |
| test-theme.mjs | OS初期配色、明示選択と保存の優先順位、OS変更、保存不可環境。レビュー入口の配色同期・CSS読み込み後のフォント候補表示はモック用 |
| test-copy.mjs | タップ表示とコピーの分離、外側操作・Escape・スクロールによる非表示、フォーカス移動、コピー対象の文字列、行番号除去、空白・改行、3秒後の復帰、連続コピー、拒否・失敗・再試行 |
| test-sharing.mjs | 公開URL・日本語タイトルのエンコード、記事・Aboutの共有先、スターのみの読み込み・重複防止、エラー通知、一覧・レビュー等での非接続 |

モックの収録画面は[モックREADME](../mock/README.md#収録画面とソース)を参照する。スクリプトの検査はブラウザの描画・実際のクリップボードへの貼り付け・アクセシビリティの適合性評価を代替しない。

## 画面と操作の確認

基本は全対象画面を400px／1280px・ライト／ダークで確認する。追加の320px・360px・768pxではナビ、長いタイトル、本文、画像、表、コード、ページ送りの収まりを重点確認する。

| 対象 | 確認すること |
| --- | --- |
| 共通枠 | 中央のサイト名・ナビが折り返す。ページ全体に横スクロールが出ない。ヘッダーは固定しない |
| ホーム・一覧 | 紹介はホーム初ページのみ。画像・タイトル・日付・要約が一つのリンク。0件・1件・先頭／途中／最終ページ、要約なしでも成立する |
| About | 記事と共通の日付表示・更新日判定、シェア・はてなスターがある。共有・スターの対象は公開About URL。タグ・前後記事はない。現行本文を使う |
| 分類・Archives・404 | 分類名と件数、年月と日付、復帰導線が読める。記事が少ない場合も不要なページ送りを表示しない |
| 本文 | H2〜H6の階層、H5／H6の区別、和欧文・長いURL・リスト・引用・脚注。リンクの文字色は周囲から継承し、常時下線はmuted、操作時の下線はtext |
| 画像 | 1200×630を基準に、幅720pxなら高さ378px。ほかの比率も切り抜かず、高さ上限で縮めない。本文画像と動画も確認 |
| 表・コード | 表は横罫線中心。長い行は領域内で横スクロールでき、ページ全体は動かない。キーボードでもスクロール可能 |
| コピー | 言語・ファイル名あり／なし、未知の言語、行番号・強調行。コピー後に貼り付けて原文と照合し、失敗後に再試行する |
| フォーカス | Tab順序、リンク全体の輪郭、配色ボタンの読み上げ名。ホバーだけに依存せず、要素を拡大しても輪郭が切れない |
| 配色 | 初回OS追従、明示切り替え、再読み込み、OS変更、ストレージ無効。本文とコードを同じモードで描画し、ちらつかない |

コード本文と言語ラベルの左端が揃い、本文左右paddingが16px相当であること、ナビ横gapが24px／16px相当、タグ横gapが8px相当、記事末尾タグ・分類一覧の左右paddingが4px相当、既定文字サイズ16pxでガターが基本24px、639px以下かつホバー不可の場合のみ16pxであることを確認する。角丸は大8px・小4px、SVGはコピー・配色16px／シェア・プロフィール24px相当とし、本文スケールとインラインコードの組版は維持する。

テキストナビは最小高さ4.8rem、ページ送りは最小幅も4.8remを確認する。アイコンは大（シェア・プロフィール）4.8rem四方・SVG2.4rem、小（コピー・配色）3.2rem四方・SVG1.6remとし、操作領域の角丸はともに4pxとする。ヘッダーナビ・タグ／カテゴリは自然幅で、短いラベルの文字間隔、対象同士の重なり、狭い幅での折り返しを確認する。文字拡大時にテキスト操作部品の高さが伸びること、本文内リンクと公式スターに寸法を強制していないことも確認する。

スクリーンショットの目視とDOM寸法の確認を併用する。全画面の寸法が範囲内でも、読みやすさや文字色のコントラストが保証されるわけではない。

### 脚注参照の行送り

本文内のsupだけにline-height: 0を指定し、上付き位置・文字サイズ・リンクのpadding・subは変更しない。脚注参照のある行でも本文の行送りが広がらず、通常・文字拡大時に数字が隣接行へ接触しないことを確認する。脚注ブロックとhrの既存余白は維持し、本文末から罫線までの距離は親子marginの相殺を含めて測る。

### ヘッダー右上の配色ボタン

配色・コピーの操作領域32px四方、内部余白8px、角丸4pxが共通であることを確認する。ヘッダー上余白はデスクトップ約69.63px・モバイル64px、コードラベルの右余白は48px相当を維持し、操作領域の寸法から独立していることを確認する。コピー背景面は24px四方で、ブロック内側の上端・右端から12px相当の位置に表示する。

自作SVGはすべて`viewBox="0 0 24 24"`で、共有・プロフィールは24px、配色・コピーは16px相当で表示されることを確認する。月・太陽は16px表示時に線幅がともに1px相当となり、外周の線が切れないことを両配色で確認する。ロゴは形・縦横比・中央配置を維持し、個別のviewBoxやtransformによる補正が残っていないことを検査する。

全ページの配色ボタンが1つだけで、通常画面では初期HTMLからsite-header直下にあり、site-navに含まれないことを確認する。320px／400px／768px／1280px・両配色・通常／1.25倍／2倍の文字サイズで、操作領域の右端と本文コンテナの右端が一致し、SVGの光学的な右補正がないこと、サイト名とボタンの間に8px相当以上の余白があることを確認する。サイト名と文字ナビの中心軸、Tab順序、内側のフォーカス輪郭、配色切り替えも確認する。旧toggle-positionパラメーターでは配置が変わらず、内部リンクへ引き継がれないことを確認する。レビュー入口の配色ボタンはレビュー用ヘッダー内に維持する。

### 光学的な左揃え

記事末尾・Aboutのシェア・Tags／Categories一覧で、本文左端に対するタグ文字の配置開始位置とSVG表示領域の左端を比較する。通常サイズの補正量はタグ・分類4px、シェア12px。サービスごとのpathの端ではなくSVG要素の箱を測る。折り返した各行、はてなスターが横にある状態／次行へ移る状態、0件のタグも確認する。クリック領域48px・シェアとプロフィールの列内gap8px・シェアとスターのgap16px相当、フッターの中央揃えを維持する。

通常・文字2倍、320px／400px／1280px、両配色で、対象リンクの矩形と内向きフォーカス輪郭が画面内に収まることを確認する。hover: noneでガター16px・文字2倍の場合はシェアの理想補正24pxを16pxに抑え、SVGの左端には8pxの余裕を残す。本文幅の横はみ出し検査だけでなく、負のマージンで左へ出た操作領域を直接測る。

### コードのコピー操作

- 言語なしの1〜2行、言語・ファイル名あり、長い名前、行番号付きのブロックを確認する。常設ツールバーはなく、ラベルは指定時のみ表示する。外周16px相当、ラベルとコードの行ボックス間8px相当、左端の一致を確認する。1行のコードも上下余白が16px相当になること、長いコードがpre内でスクロールすることも確認する。コードの文字サイズ・行高・公式配色は維持する。
- ホバー・Tabによるフォーカス・コードのタップでアイコンが現れ、コードの幅・高さ・位置が変わらないことを確認する。最初のコードタップではコピーせず、表示されたボタンの操作でのみコピーする。
- 既定文字サイズ16pxで実際の操作領域32×32px、背景面24×24px、SVG16×16px、1行ブロックは約52.2px（横スクロールバーなし）を確認する。320px／400px／1280px・両配色・文字2倍でもボタンの四辺がブロック内に収まることを確認する。
- 右上のコードが隠れた場合、Escape・ブロック外の操作・コードの横スクロールでアイコンを隠せることを確認する。Copyにフォーカスがある場合のEscapeはコード本文へフォーカスを移す。再タップ・マウス再進入・フォーカス移動で再表示できること、長押し選択・ドラッグ選択・横スクロールを妨げないことを実機でも確認する。
- コピー後に貼り付けて原文と照合する。成功はチェックと読み上げ通知、3秒後は通常アイコン、失敗は×と再試行・手動選択の案内になることを確認する。表示状態や結果によってコードのレイアウトが動かないことも確認する。
- JS無効時はCopyがhiddenのままで、コードの手動選択が可能であることを確認する。

## 見出し余白と補助文字

補助文字3段階（本文の0.910／0.829／0.754倍）と一覧タイトル1.207倍、本文画像・表・コードの前後余白1.931emを確認する。ナビはモバイルも本文の0.910倍とし、320pxで折り返しと操作領域を確認する。

本文内のH2〜H6が前2.121em・後0.687emを基本とし、直後の段落の上marginが0、連続する下位見出しの前marginが0.910emであることを確認する。記事タイトル・同階層見出し・独立ブロックの間隔は維持する。本文先頭要素の上余白0、マージン相殺後の実間隔も確認する。本文17px時の見出し→段落はH2約17.00px、H3約15.49px、H4約14.10px、H5約12.84px、H6約11.68px。連続H2→H3は約20.51px、H3→H4は約18.67pxとし、サブピクセルの丸め差を許容する。

## コンテンツ・更新日・フィード

### モバイルの前後記事ナビゲーション

レビュー入口の代表ページ「前後記事あり」「長い実記事・Nextのみ」「Prevのみ」を使う。

前後記事は全画面幅で左右同幅の横並びとし、列間はデスクトップ24px・639px以下では16px。新しい記事へのPrevを左、古い記事へのNextを右に固定し、一覧のページ送りと時系列を揃える。片方だけでも位置を維持し、長いタイトルは切り詰めず折り返す。320px／400px・両配色で、長いタイトルの行数、操作範囲、左右の判別性を確認する。

ページ送りと前後記事のラベルは`« Prev`／`Next »`で共通。記号と文字の間隔を実画面で確認し、前後記事では記事タイトルだけにホバー下線が付くことも確認する。

ページ送りは1行配置を維持する。ホーム・記事一覧の最初／中間／最終ページを両配色・通常／拡大文字で確認し、文字の間隔と操作領域の重なりを分けて評価する。Chromeで既定16pxを基準とする文字2倍・400px幅では重なりなし。320px幅では文字は重ならないものの間隔が狭く、左右リンクの操作領域と中央番号に約2.5pxの重なりがある。より狭い幅や異なるフォントでは文字も重なり得るため、ラベル短縮は発生範囲を減らす措置であり、すべての拡大・幅の組み合わせで重なりを防ぐ保証ではない。実際のhtmlのfont-sizeも記録し、ブラウザ設定と検証用拡大の二重適用を区別する。

ホームの紹介文が現行Hugo設定と一致し、2ページ目以降には表示されないこと、Aboutが現行本文から生成されることを確認する。更新日は`.Date`と`.Lastmod`の表示上の年月日が異なる場合だけ表示する。dateのみ指定して補完された場合・同日時指定・同日の時刻差では非表示、別日なら表示、更新日がゼロ時刻なら非表示を確認する。公開日・更新日の横gapは1.6rem、タグの横gapは0.8remを確認する。記事詳細・About・一覧・Archivesのタイトルと日付の間隔は0.8rem。Archivesではmargin値だけでなく、タイトルと日付の行ボックス間が8px相当であることを実測する。月名と先頭記事のベースライン、長いタイトルの折り返し、タイトルだけのホバー下線、日付を含むリンク全体のフォーカスを確認する。記事間24px・月間32pxで、最終項目に余白が重ならないことも確認する。分類一覧は件数を除いて分類名だけにホバー下線が付くことを確認する。前後記事は両方あり・Prevのみ・Nextのみの各状態でデスクトップの左右位置が変わらず、モバイルでも左右同幅の2列・列間16pxになることを確認する。

本実装ではHugo標準の名称順、1ページ10件、各RSS（home/section/taxonomy/term）の既存URL・対象範囲・要約・無制限・自動検出を確認する。画面上の更新日表示条件がRSS・OGP・構造化データの日付出力に影響しないことも検査する。カバーなし記事にOGP画像を出さない。外部埋め込みの実動作は本実装時に検証する。

## フォント・palt

本文・記事見出し・サイト名はApple標準＋Segoe UIを共用する。コードはMenlo → Consolas → monospaceを確認し、和文候補は明示しない。ブラウザの「実際に描画されたフォント」とCSSの候補リストを区別する。

- MacのSafari／Chrome／Firefox：本文のSan Franciscoとヒラギノ、サイト名300と本文400／見出し500／強調700の階層と記号類を確認。コードは欧文Menloと、日本語コメントのフォールバック・字幅を確認。
- Windows：本文のSegoe UI＋Noto、サイト名300と見出し500の実フェイス、本文400との差を確認。コードは欧文Consolasと、ブラウザが選ぶ和文コード書体の字幅・鮮明さを確認。本文のNotoあり／なしとは分けて検証する。候補が存在するだけで良好な描画を保証しない。
- Linux／Android：Menlo・Consolasがない環境でも、コードの欧文iiii／WWWW／0000が等幅になることを確認。Noto Sans CJK JPだけが導入された環境も対象とする。和文は本文との一致ではなく、字幅と読みやすさで評価する。
- iOS／Android：日本語フォールバック、本文・インラインコードのベースライン、長文と小画面での可読性を確認。特にiPhone Safariはルート62.5%・本文1.7remで和文が読みやすくなるか確認し、コードの14px相当・行高1.3で日本語コメントや強調行が詰まりすぎないか確認する。
- palt：入口の同一文で有効／無効の差を確認。コードに継承しないことも確認する。
- インラインコード：文字と背景の余裕、行送り、隣接行の背景の接触を確認。paddingによる折り返しの増加は行高増加と区別する。

必要なら対象端末のフォントファイルを明示し、再検査する。インストールやWeb配信は不要。

```sh
node mock/inspect-fonts.mjs /path/to/font.ttf /path/to/font.ttc
```

このツールは名前、版、GPOS／GSUB、アウトライン・ビットマップテーブル、名目送り幅を読む。実際のブラウザ選択・シェーピング・可変軸全体の描画は検査しない。

## 文字サイズとズーム

ブラウザの既定文字サイズを16px・20px・32pxに変え、元の設定へ戻せるよう値を控える。期待する本文サイズは次のとおり。

| 既定文字サイズ | 本文：ルート62.5%・1.7rem | コードブロック：1.4rem |
| --- | ---: | ---: |
| 16px | 17px | 14px |
| 20px | 21.25px | 17.5px |
| 32px | 34px | 28px |

H6→H1のサイズは本文の1、1.099、1.207、1.326、1.456、1.6倍とし、丸め前の倍率`1.6^(1/5)`に基づく5区間の階層を確認する。見出しのem指定の余白も拡大するため、長い見出し・連続する見出し・段落とのマージン相殺を確認する。記事タイトルは本文の1.6倍、サイト名は1.931倍。コードは本文基準トークンと独立した1.4remとする。本文基準を変更した場合に、見出しとモジュラースケールの余白だけが追従し、コード・独立UIの寸法が変わらないことも確認する。この表はCSSの計算サイズであり、Safariの和文の見た目上の縮小とは区別する。コード行高は1.3（標準設定で18.2px）。本文最大幅720pxは変えずに折り返す。固定高さによる文字・ボタンの切れがないか確認する。

ネイティブの200%ズーム、1280pxを400%にした320 CSS px相当のリフローも別に確認する。viewport幅変更、既定文字サイズ変更、ブラウザズームは同じ試験ではない。[W3C Resize Text](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)、[Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)

レイアウト負荷を手早く再現する場合だけ、次の一時ビルドを使う。

```sh
node mock/build.mjs --text-scale=1.25
# 各画面を確認する
node mock/build.mjs --text-scale=2
# 確認後、必ず通常ビルドへ戻す
node mock/build.mjs
node mock/verify.mjs
```

これはmock/site/を一時的に上書きしてルートの割合を拡大する検証であり、ブラウザ設定を変更するものではない。verify.mjsは検証用styleの残留をエラーにする。

## 引用線と見出しリンク

見出しリンクの記号サイズは`--text-label`（本文17px時は約12.82px）とする。ライト・ダークで、見出しリンクのmutedと共有・プロフィールアイコンの本文色がホバー前後で変わらないことを確認する。本文・脚注・ヘッダーナビ・ページ送り・タグ・分類一覧・Archives・前後記事・コピーも通常時の前景色を維持し、テキストの下線・コピー表示中の背景と内枠・キーボードフォーカスは残り、シェア・プロフィール・配色・コピーにホバーによる追加装飾がないことを確認する。

常時下線の本文・引用・キャプション・脚注・現在地リンクは通常muted、ホバー・キーボードフォーカス時はtextとなることを両配色で確認する。通常下線なしのナビ・ページ送り・タグ・一覧タイトル・分類名・Archives・前後記事タイトルは、ホバーとキーボードフォーカスで同じ部分だけにtextの下線を表示する。件数・日付・要約・前後記事ラベルへ下線が広がらず、サイト名・見出しリンク・アイコンは下線なしを維持する。太さ1px・オフセット0.26em・文字色・フォーカス輪郭・配置が変わらず、訪問済みでも同じ表示になることを確認する。

引用専用の罫線が両配色のOverlay1であること、一般の境界線が変わらないことを確認する。引用内のリスト・コードも使用する。

本文H2〜H6の見出しリンクは、ホバー・キーボードフォーカス時のみ表示する。400px／1280px・両配色と320pxで、表示前後の見出し行数・本文位置が変わらないこと、クリック・Enter・URL再読み込みで対象節へ移動できることを確認する。ホバーできないタッチ主体の環境ではリンクがdisplay: noneとなり、Tab停止もないことを確認する。外部からのフラグメント指定は引き続き機能する。引用・リストの字下げ領域内でも他の要素と重ならないことを確認する。

320px／400px／768px／1280pxで通常・1.25倍・2倍の文字サイズを確認する。ホバー可能環境の共通ガターが`max(24px, リンク操作幅)`となり、見出しに左paddingがなく、本文と左端が揃うことを確認する。既定文字サイズ16pxから拡大した場合、ホバー可能環境のガターはモバイル・デスクトップとも24px／30px／48pxとなる。本文・ヘッダー・フッターは同じ幅と位置を共有し、十分に広い画面では最大幅720pxの配置が変わらないことも確認する。scrollWidthだけでなく、リンクと記号の左端が画面内にあり、フォーカス枠の四辺が欠けず、見出し文字と重ならないことを確認する。ホバー・フォーカス前後で見出しが移動せず、`hover: none`では639px以下が16px、それ以外が24pxになることも確認する。

## 確認済みの範囲と本実装で残る確認

ガターの境界条件は639px／640pxとhover: hover／noneの組み合わせで確認する。既定フォント12pxでもホバー可能環境のガターは24pxを下回らない。ホバー不可では既定フォントサイズにかかわらず639px以下は16px、640px以上は24px。本文最大幅720pxによる中央揃えの余白と、ガターの下限値を区別する。

CopyからTabでコード本文へ移動し、Copy・コード本文それぞれのフォーカス枠の四辺が内側に欠けずに見えることを、両配色・デスクトップ／モバイル幅で確認する。矢印キーでコードを横スクロールできることも確認する。動画の前後余白は本文基準1.931em、Archivesの日付は本文の0.829倍。短いCategoriesと長いArchivesの往復で、通常型スクロールバーが出入りしても本文とサイト名が横移動しないことを確認する。

本文部品の組み合わせ見本で、引用内のリスト・コード、複数段落と入れ子リストを含む項目の余白・字下げ・局所スクロール・フォーカスを検証する。定義リストとdetails/summaryは今回の対応追加には含めない。

モックの自動テストと、macOS Chromeの主要画面・両配色・狭い幅・文字拡大は確認済み。WindowsでのSegoe UIの300・500、iPhone Safariの本文・コードの可読性、ブラウザの既定文字サイズ変更はユーザー確認済み。フォントの実測結果と注意点は[実装上の判断理由](05-theme-implementation.md)を参照する。ブラウザ版・設定の網羅的な記録はないため、全対象環境の検証を代替しない。

a要素のtext-underline-offsetは0.26emとする。Windows実機で和文・欧文の下線位置、複数行リンク、ホバー時の下線を確認する。SVGアイコンリンクには下線を付けない。

Chrome・Firefoxでは通常時・ホバー時・現在地表示の計算済み`text-decoration-thickness`が1pxであることを確認する。対象はヘッダーナビ、ページ送り、記事末尾タグ、本文・脚注のリンク、一覧・前後記事・Archivesのタイトル、分類名。下線は必要な要素だけに現れ、日付・件数・前後記事の方向ラベル・アイコンには付かないことを確認する。100%と拡大表示で太さを比較する。自動検証では`text-decoration`一括指定の混入と、下線を描く要素への太さ指定漏れを検出する。

下線の1px指定と対象別のホバー表示はChromeで確認済み。Firefoxでも意図した太さで表示されることをユーザー確認済み。

本実装では次を確認する。

- Windows・iOS・Android・Firefox等の実機描画、日本語混植、スクリーンリーダー、コントラスト、ネイティブズーム。
- ページ背景と本文・補助文字・リンク・操作部品のコントラストを評価する。コードブロックのシンタックスハイライトは公式Catppuccin配色を維持し、このコントラスト調整の対象外とする。
- JS無効でも本文・一覧・通常リンクを利用できること。コピー・配色ボタンの利用不可状態を適切に扱うこと。
- シェア・はてなスターの[実動作確認](07-theme-sharing.md#検証)に従い、通信・追跡防止・レイアウト変動を確認する。本文中のX等の埋め込みはモックでは未接続のため、本実装で別途確認する。
- 実際のHugoテンプレートで全記事・一覧・分類・ページ送りを生成し、既存URL、画像・動画、RSS、canonical・OGP・JSON-LD、公開環境とプレビューの違いを確認する。
- 性能は[移行時の確認](03-papermod-analysis.md#性能の確認)に従って本番相当の内容で測定する。モックのページ数・ファイルサイズだけで性能やWCAG適合を判定しない。
