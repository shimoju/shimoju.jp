## 意見と選び方

### 操作ラベルの英語統一

英語統一に賛成。今回のサイト名やAbout／Archivesと組み合わせるなら、操作の語彙も揃えると見た目が落ち着く。ただし「英語にすれば無条件に使いやすい」とは考えず、Previous / Next / Copyなど短く一般的な語に絞る。文章や記事タイトルまで英訳しない。アイコンだけにせず、読み上げラベルも用意する。

「コピーしました」に相当する成功表示は、統一案に合わせてCopiedとした。Hatena Bookmark／Hatena Starも同じ案の一部であり、日本語のサービス名を残す選択もあり得る。英語UIを最終確定した扱いにはしていない。

### カバー位置と所属の分かりやすさ

画像上配置は「画像→タイトル→要約」のまとまりが自然で、今回の問題には有力。下配置はタイトルから読み始めやすい。どちらも画像から次の記事へ視線が流れないよう、記事間の区切りと内部の余白を整理した。

薄い横罫線はカードの外枠ではなく、隣り合う記事の境界だけに置く。全幅の画像があるため、余白だけよりも所属が明確になる。元の画像の切り抜き・高さ制限は行わない。

### サイトタイトルとフッター

サイトタイトルは全画面統一案を推したい。今回のサイト名は短く、36px／30pxでも十分収まり、記事タイトルとは中央／左揃えの違いで役割を分けられる。ホームとの往復時に大きさが変わらない利点もある。

フッター中央揃えも、著作権とRSSだけなら過剰には見えない。ヘッダーとの対称性を好むなら中央、本文の左端から自然に読み終えたいなら従来配置、という違い。比較案のまま残す。

### クリック範囲とアクセシビリティ

クリック範囲の拡大には賛成。ただし範囲の広さだけでアクセシビリティ全般が向上したとは言えないため、今回はJavaScriptで記事コンテナーにクリックを付ける方法ではなく、ネイティブの一つのリンクにまとめた。

リンク名は`aria-labelledby`で記事タイトルだけを参照し、長い要約全体をリンク名として読み上げさせない。新しいタブで開く操作やキーボード移動を維持し、同じ記事に複数回Tabで停止することを避ける。フォーカスは記事全体の輪郭で示す。記事内へ別のボタンを追加する場合は、リンクの入れ子にならないよう再設計が必要。

## Hugoで言語・ファイル名を表示できるか

どちらも可能。ただしファイル名のバーを自動表示する標準Markdown機能ではなく、Hugoの属性記法とカスタムレンダーフックを組み合わせる。

````markdown
```toml {filename="config.toml" linenos=inline hl_lines=[3]}
# 日本語コメント
[tools]
ruby = "3.4"
```
````

レンダーフックでは、言語は`.Type`、独自属性は`.Attributes.filename`、行番号・強調行などは`.Options`に分かれる。これらは[Hugo公式のコードブロックレンダーフック仕様](https://gohugo.io/render-hooks/code-blocks/)に記載されている。

今回は[実際のフック](../mock/src/render-codeblock.html)を一時Hugoサイトの`layouts/_markup/render-codeblock.html`として実行した。`transform.HighlightCodeBlock`でハイライトし、未指定・未対応の言語はプレーンテキストへフォールバックする。`markup.goldmark.parser.attribute.block`の追加設定なしで、このコードフェンス属性を取得できた。

Hugo v0.165.0で、[部品Markdown](../mock/src/specimen.md)からTOML · config.toml、EXAMPLE-UNKNOWN · example.txt、行番号、強調行、言語なしブロックを生成し、出力とChrome表示を確認した。旧モックの「本文にconfig.tomlが含まれるか」でラベルを推測する処理は削除した。本番のHugo設定・テンプレートは変更していない。

言語もファイル名もないブロックは上部領域を44pxから32pxへ、本文側の上パディングを12pxから0へ縮めた。Copyの操作領域は32px以上を保つ。ファイル名が長い場合はラベルが折り返せる。

## 検証

検査スクリプト：

```sh
node mock/build.mjs
node mock/verify.mjs
node mock/test-theme.mjs
node mock/test-copy.mjs
```

- 静的HTML33ページ・内部参照416件を検査。目次ページの削除、旧比較の撤去、ページ送り、Hugo由来のラベル、一記事一リンクを含む。
- 配色のOS追従・保存・新しい比較条件・旧条件の無効化を単体テスト。
- コピーする文字列、行番号の除去、3000msの復帰タイマー、連続コピー、失敗、再試行を単体テスト。
- ChromeでCopied表示を確認し、復帰後はCopyで再操作可能。成功前後で行番号付きコードブロックの高さは160pxのまま。下部の可視通知はない。
- Chromeで一覧の要約部分とArchivesの日付部分をクリックし、記事へ移動することを確認。比較条件も遷移先へ保持する。
- フォント候補順はレビュー画面でCSSの実値を表示。モバイル本文16px・タイトル25.6px・サイト名統一案30px、コード14px／21pxを測定。
- 全33画面を320・360・400・768・1280pxの両配色、計330条件で巡回し、横はみ出し・画像欠落なし。新しい比較条件を適用したホーム・記事・404も、4幅の両配色で24条件確認した。
- 最終測定と新比較案の結果は[第2案の検証データ](../mock/verification/browser-checks-v2.json)に記録した。初版のデータは別ファイルに保管している。

ブラウザ操作側の仮想クリップボードにはデータが渡らず、この回はAPI経由の貼り付け確認ができなかった。実際の`writeText`成功後の表示、タイマーによる復帰、渡す文字列の単体テストを確認範囲とし、貼り付けまでの再確認済みとはしない。

macOSのChromeで検証。別OSの実フォント、実サービスのシェア／スター連携、ネイティブズーム倍率の操作、WCAG全項目の適合までは保証しない。これらは今回のデザイン比較の採否とは分けて扱う。
