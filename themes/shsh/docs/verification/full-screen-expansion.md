# 全画面への展開（T010）

R004で承認された共通設計を、About／通常固定ページ、Archives、タグ・カテゴリ一覧／個別分類、404、記事末尾のタグ・前後記事へ展開した。全画面レビューR002は、サイト入力の移行と全公開出力の照合後にT014で提出する。T010の実装・比較だけで移行完了とはしない。

[40画面の比較画像](t010/index.html)・[画面とfixture URLの対応](t010/cases.json)・[統合検査ログ](t010-check.log)を参照する。

## 構造

- `posts.html`の共通記事集合を、Archivesと前後記事にも適用。日付降順・同日時の公開パス順、複数mainSections、Hugoの公開フィルターを共有する。Archivesの年・月は`local-time.html`でサイトのタイムゾーンへ揃える。
- 分類一覧は記事集合に属する件数を数え、固定ページだけの分類を表示しない。個別分類は`list-pages.html`→`post-list.html`→`pagination.html`を使い、10件既定・設定変更・0件表示を既存一覧と共有する。
- `article-end.html`が記事末尾の構成を担当し、`engagement.html`は共有・スター部分だけを生成する。通常固定ページにはタグ・前後記事を出さない。前後ともない単独記事では空ナビを作らない。`navigation-label.html`を一覧と記事間移動で共有し、左Prevが新しい記事、右Nextが古い記事。
- `discovery.css`は分類・Archives・404、`article-end.css`は記事末尾のタグ・前後記事を担当。既存の本文尺度・UI尺度、行高、リンク間隔、光学インセットを再利用する。共有・スターの内部は`sharing.css`に保持。新しいTypeScriptは追加していない。
- `page-title.html`は自動生成された分類ページの名前を入力どおり保持し、明示的な分類ページはそのタイトルを尊重する。表示・HTML title・OGP・RSSで共用する。Hugoの自動タイトル化により`chezmoi`等が大文字化されることを比較で検出した。[HugoのData.Term](https://gohugo.io/methods/page/data/)と生成結果を照合した。
- 個別分類のナビは親分類を現在位置として示す。タグ列は`role=group`で読み上げ名を持つ。これらは凍結モックの表示を維持する内部実装の是正。

## 比較と境界

`build-review-fixture.ts`で実記事5件・About・Archivesを隔離生成し、`build-full-review.ts`で分類ページ送り、空集合、1記事・要約なしのfixtureを生成する。凍結モック42ページのうち40製品画面を全件対応付けた。診断入口はテーマの対象外、本文部品は既存の`review.spec.ts`が担当する。

外部通信はブラウザで固定応答。比較用X shortcodeだけはモックと同じリンク文面を生成し、外部サービス由来の高さ変動を除く。本番の組込shortcodeを代替する実装ではない。共有・スターの実サービス接続や投稿の検証でもない。

3エンジンの40画面×1440／390px×両配色で、共通枠・各一覧項目・分類項目・Archives・記事本文・末尾・404を比較する。表示されていない空要素は寸法比較から除き、見える要素の個数と各座標・寸法を0.06px未満で照合する。125／200%文字拡大で横溢れを検査する。画像はChromiumの320枚を保存し、他エンジンは寸法とaxeの証拠を保存する。キーボード・JS無効時の前後移動／分類ページ送り／404復帰、固定ページの日付非表示も別途検査する。

HTML-validateはproduction／preview・3境界fixtureの全HTMLを検査する。長い実記事「2026年、開発環境を一新した。…」のタイトルは変更せず、`long-title`という70文字のSEO目安だけを**その正確なタイトル文字列に限定**して許容する（F015）。他のタイトルやHTML構造の検査を無効化しない。axeはChroma内の色対比だけを既存合意どおり例外とする。

## 発見した問題と残件

- **F014（判断待ち）**：Aboutの業務経験表に空の列見出しが2つあり、axeの`empty-table-header`で不合格。入力は`| 業務経験 | | |`。提案は`| 業務経験 | 技術 | 経験年数 |`。表示と内容が変わるため、資料5 Q1に従い判断を依頼した。現時点では入力も期待値も変更していない。比較画像の一致をアクセシビリティの合格と混同しない。
- 既存表の問題を無視せず、検査は失敗を報告したまま全条件の画像と結果を収集する（Playwrightのsoft assertion）。F014を合格・例外にしていない。
- 初回の全統合検査で、1記事fixtureの4190ポートがFirefox／WebKitで開けず、4件の検証が停止した。ブラウザのポート制限に当たる検証環境の問題として4195へ移し、失敗した比較と操作を再検証する。[WebKitの4190制限](https://bugs.webkit.org/show_bug.cgi?id=156986)を参照。
- T012のサイト設定・全埋め込み移行、T013の全公開出力照合／CI、T014のR002提出、実機・性能・Cloudflare配信確認は未完了。

## 検証結果

全統合は218/225成功（3.5分）。Aboutの3件と検証用ポートの4件が失敗した。ポート変更後の影響6件は3エンジンで成功（7.8秒）。有効な結果を合わせると222/225成功で、Aboutの3件だけが未合格。[ポート修正後のログ](t010-port-recheck.log)を併せて参照する。

40画面の480条件すべてで寸法比較が一致し、最大差は0.03418px。320画像と480条件のaxe記録を保存した。Aboutの空thは12条件で検出され、画像比較と寸法の一致をもって合格にはしていない。既存102件の回帰検査・全生成HTML・分類と日付境界の静的検査は成功。凍結モック68ファイルのハッシュ不変を確認した。Archivesのモバイルダーク、分類一覧のPCライト、末尾Prevのみのモバイル記事を画像で目視した。

## 再現

テーマルートから実行する。

```sh
pnpm check
node scripts/build-full-review-report.ts
pnpm review
```

比較ページは`http://127.0.0.1:4184/t010/`。`pnpm check`はF014解消前にはAboutで失敗する。生の寸法・axe記録は`.cache/full-review/`、提出物は`docs/verification/t010/`。公開サイトにはfixtureと比較ページを含めない。
